# M5–M8 实施计划与原型资料清单

> 历史阶段计划：保留编写当时的设计、安排和判断，不作为现行功能或操作说明。当前范围见[实现状态](../../development/implementation-status.md)、[业务规则](../../business/rules.md)与[运行维护](../../operations/runbook.md)；同目录背景见[历史索引](../README.md)。新发票不再以 M3 实物箱整组确认为前置条件，外部业务操作继续由人员执行。

## 1. 目标与已确定边界

本轮完成 M6 物流与交接、M7 报关与 9810、M8 费用与归档，并按你的选择补齐 M5，形成完整的本地业务闭环。

- **领星继续只读**：创建单据、分配库存、确认发货、修改备注和费用，由人员在外部系统操作；本系统负责准备、登记、核对和留档。
- **首期范围**：现有丰信物流模板及美国、欧洲报关样本。
- **费用分摊**：人工指定各单金额，系统校验同币种合计守恒。
- **报关分组**：默认按主体、国家、申报方式、币种等条件拆组；跨国合并逐组确认依据。
- **完成标准**：可运行功能、自动验证和模拟闭环通过；真实平台导入、真实批次和人工签收另行验收。

## 2. 分模块实施

| 模块 | 建设内容 | 完成条件 |
|---|---|---|
| **M5 单据与库存分配** | 从有效 M4 单据建立发货准备组，维护出库仓、商品、组合关系、辅料、物流及备注；登记外部单号、实际明细、库存分配、缺货及取消结果，上传核对凭据。准备范围与外部结果逐项对账。 | 单号、成员数量、仓库及分配结果一致；缺货、未知或范围不一致继续待处理。库存查询仅作为参考。 |
| **M6 物流与交接** | 直接引用 M4 已生成并复核的丰信文件；登记提交版本、接收或拒绝反馈；维护物流订单、跟踪号、箱唛、物流毛重及计费重；提供放行检查、按箱部分交接及领星发货结果核对。 | 放行前依赖齐全；交接准确关联内部箱 ID；实际交接与领星发货分别记录，差异可追踪。异常情况下已发生的交接仍可登记并生成待办。 |
| **M7 报关与 9810** | 建立独立报关分组，生成现有样本对应的七页资料：报关单、申报要素、填制规范、发票、箱单、合同、委托书；提供校验、复核、退回修订。报关和 9810 分别登记状态、外部编号、反馈附件及提交版本。 | “已保存、复审通过、已申请、确认成功”分别呈现；未知结果保持待核对。没有独立 9810 导入模板时，提供填写核对清单及人工结果登记。 |
| **M8 费用与归档** | 接收原始账单，支持标准 XLSX 导入及人工补录；维护费用类型、币种、收费范围和逐单分摊；生成拟回填清单，登记人工回填前后值及核对凭据；支持补账、退款、结清检查和归档。 | 分摊守恒、费用结果有依据；全部有效成员满足条件后，生成归档 ZIP、文件哈希及关联记录清单。补账或更正重开待办，保留旧归档。 |

实施顺序为：**公共基础与 M5 → M6 → M7 → M8 → 全链路验证**。M7 草稿可以提前准备，正式生成与完成检查等待所需物流数据。

## 3. 页面、接口与数据基础

- **页面**：在现有发货管理中增加“领星单据与分配”“物流与交接”“报关与 9810”；启用“费用对账”，批次详情增加完成条件和归档入口。沿用现有筛选、表格及分步弹窗。
- **接口与契约**：新增 M5、物流、报关／9810、费用和归档接口及共享类型，覆盖草稿、预检、提交、复核、外部结果和历史查询；本地修改继续采用 `operationId` 与预期版本控制。
- **关联范围**：M5、物流订单、报关组分别维护成员关系，不强制一对一。部分交接及申报关联具体箱子和商品数量，防止重复占用或重复完成。
- **版本与文件**：复用现有文件索引、SHA-256、审计及 Worker。来源变化使受影响复核失效，已经发生的外部事实保留；文件生成任务在发布前再次检查依赖。
- **兼容与默认**：采用增量迁移，不补造历史完成状态。M4 丰信生成器继续复用；M7 新增独立模板适配器，运行模板采用清理后的 XLSX。未确认的净重、单位换算及辅料公式先使用人工复核值，不从历史数字推算默认规则。

## 4. 验证与交付

- **M5**：多单部分成功、缺货、范围不符、取消后结果核对，以及重复提交和版本冲突。
- **M6**：箱唛错配、缺项阻止放行、部分交接、重复交接、实际已交但领星未发货。
- **M7**：七页内容与打印布局、数量和重量合计、商品与运费币种、跨国合并确认、退回重提及来源变化后复核失效。
- **M8**：合并收费分摊、混币种分别核对、空值与零费用、退款补账、归档阻塞及重新打开待办。
- **整体**：隔离数据库与浏览器模拟完整闭环，检查备份恢复后的文件和关联；执行类型、lint、测试、构建、隐私检查，并回归 M2–M4。

交付包括页面、接口、迁移、模板适配器、验证脚本、操作说明及技术验收记录。

## 5. 需要补充的原型资料

**已有资料可直接复用，无需重复提供**：丰信空白模板与已填样例、美欧七页报关样表、《制作发票》《填写报关资料》《清关》操作文档，以及月表费用汇总样式。

需要补充的重点是当前业务操作和输入输出样例，**不要求你制作完整 UI 设计稿**。

| 模块 | 优先补充资料 |
|---|---|
| **M5** | 当前领星一套完整单据的截图或导出：创建、出库仓、商品／组合、辅料、分配结果、发货结果；再补一个缺货或分配失败案例。提供仓库映射、组合明细、辅料数量与费用关联规则。 |
| **M6** | 丰信接单回执或订单导出、原始箱唛 PDF、重量／计费重回传、实际交接凭据；附它们与 FBA、箱子的对应关系。拒绝和部分交接案例可随后补充。 |
| **M7** | 现有截图与当前平台的变化；报关及 9810 成功、退回、待核对的页面或反馈样例；电商订单号来源和关联案例；净重、单位换算、取整及币种规则。若平台支持批量导入，再提供独立 9810 模板。 |
| **M8** | 一份原始账单及人工核对后的逐单分摊结果，至少包含一笔合并收费；费用编辑前后截图或导出。退款／补账案例和现用归档清单可随后补充。 |

**建议第一批先给**：M5 完整操作样例、M6 订单回执与箱唛、M7 当前成功／退回状态、M8 原账单与分摊结果。尽量选择能相互关联的同一票业务，并保留关联编号一致性。

有一项需要资料明确：旧 SOP 的辅料费用关联，文字写“整箱”，截图显示“整单”。实施时先保留逐单选择，待当前实单样例确认后再固化规则。缺少成功或失败样例的部分使用合成数据完成技术验证，并明确保留真实业务待验项。
