# T12 + M2 完整制表链路实施方案

> 历史阶段计划：保留编写当时的设计、安排和判断，不作为现行功能或操作说明。当前范围见[实现状态](../../development/implementation-status.md)、[业务规则](../../business/rules.md)与[运行维护](../../operations/runbook.md)；同目录背景见[历史索引](../README.md)。新发票不再以 M3 实物箱整组确认为前置条件，外部业务操作继续由人员执行。

## 目标与范围

完成“需求 → 周批次 → 人工分组 → 领星只读同步 → 差异处理 → 确认编码 → 月/批次成品表 → XLSX”的完整路径，覆盖 T12、T14–T21 及必要依赖。

本轮交付可运行功能、自动对账和验收证据；缺少真实样本或业务签收的范围明确标为待验。当前只读检查已通过 50 项单测、类型检查和 lint，业务代码尚未修改。

## 实施内容

### 1. 周批次与人工分组

- 新增周批次、子批次修订、版本化成员及操作幂等记录，复用现有需求、需求版本和来源关联。数据库保证周范围唯一、同周货件只有一个有效归组。
- 使用首次导入的上海业务日期归周；跨年显示周起止日期，再次导入不自动迁周或复制货件。
- 同店铺 sid、国家、业务渠道内允许人工跨 STA 计划合组或同计划拆组；来源组名、商品和配方只作参考。
- 默认按组内最小标准化 FBA 排序，支持保存人工顺序。所有修改检查管理员身份、期望版本和 `operationId`，并发冲突返回 409。
- 分组页面提供待分组清单、成员调整、排序及原文件/工作表/物理行追溯。

### 2. 正式只读同步与恢复

- 扩展现有白名单客户端，补齐令牌有效期、续约、共享缓存及跨进程请求协调。按官方错误码区分过期、无权限和签名错误；同 appId、同接口协调在途请求。[领星接入规则](https://apidoc.lingxing.com/new/guides/new-instructions/)
- 同步界面显式提供货件**创建日期范围**，优先复用上次成功范围，首次建议最近一年；范围内查无时提示调整范围。[货件列表文档](https://apidoc.lingxing.com/new/api-docs/FBA/FBAShipmentList/)
- 每个子批次建立逐票任务、逐页检查点和不可变响应快照。列表每页 100 条，检测重复页、总数变化及提前结束；不完整结果不得发布为同步成功。
- 沿用短事务领取、事务外查询、短事务复核发布模式。失败保留最近成功数据和采集时间；重试恢复未完成范围，刷新建立新运行。
- API 与 Worker 均复核当前管理员和输入版本；现有示例任务接口保持兼容，M2 使用独立任务契约表达部分成功。

### 3. 商品、箱、差异与补录

- 稳定货件复用 `sid + FBA` 身份；商品保存 MSKU、FNSKU、SKU，箱使用内部 UUID，分别保存平台箱 ID、packageId、localBoxId 和箱名。
- 强标识唯一匹配时续接内部箱；缺失、冲突或无法可靠对应时要求人工映射。首次按有效且不重复的 localBoxId 数字顺序建议箱序，人工确认后固定。
- 正式发货数量采用详情 `quantity`，必须逐商品等于装箱合计；列表申报量冲突需处理，接收差异独立提示。缺值不补零，重复记录不静默删除。
- 提供 XLSX 模板和人工补录，生成候选修订，保留来源、原因、操作者及原值；补录仍须通过完整身份和数量守恒校验。
- 补录模板固定为“货件商品”和“逐箱商品”两张表，包含 sid/FBA、完整商品身份、品名、申报量、箱关联键、箱序和箱内数量；重量尺寸及单位可选。
- 同步和补录只发布候选版本，不覆盖历史确认。

### 4. 确认、编码与更正

- 确认绑定成员、需求、商品箱数据、箱序及规则版本；过期或存在阻塞差异时拒绝确认。
- 编码前展示本次有序组集合，在周批次事务锁内分配 `A…Z、AA…`；已用及作废前缀不回收，已有编码不因排序变化而重排。
- 单纯追加新 FBA 生成待确认版本，保留原码，新箱接续编号。移除成员只作废被移除箱的编码，重新校验剩余范围。
- 未导出组合并、拆分或移动成员，使受影响旧组确认与全部旧码失效，新组重新确认并领取新前缀。
- 导出或登记打印后冻结直接修改。提供“发起更正”：创建关联的新修订，重新校验、确认并分配新前缀；旧事实和文件保留，新文件注明替代关系。
- 打印仅登记人工事实，不控制打印机，也不写回领星。

### 5. 成品表与 XLSX

- 新增周批次、子批次详情和月汇总入口，提供商品表、逐箱表、筛选、分页和横向滚动；美国与欧洲视图共同覆盖现有国家，欧洲包含英国。
- 页面和 XLSX 共用同一确认数据投影。主表保留参考字段顺序，至少十个箱列，超过后动态扩列，并附完整“逐箱明细”和“版本说明”。
- 明确使用“目的 FC”“子批次商品合计”“流程状态”“实际发货日期”；实际重量独立展示，未登记日期保持为空。
- 月表按各需求首次业务日期筛行；跨月组不拆组、不重码，确认和冻结仍作用整个组。分别表达完整组商品合计与本月数量。
- 服务端使用固定版本 ExcelJS 生成真实单元格、日期格式、列宽、冻结首行和筛选，直接写入计算结果。[ExcelJS 文档](https://github.com/exceljs/exceljs#readme)
- 导出任务固定确认、规则和模板版本；生成、回读核验后发布不可变文件，发布前再次检查版本。提供授权下载、导出历史和失效原因。

## 接口与数据契约

统一使用 `/api/v1` 前缀，新增共享 Zod 契约覆盖批次修订、同步逐票结果、候选数据、差异决定、确认、编码和导出版本。

| 接口组 | 主要行为 |
| --- | --- |
| `/weekly-batches`、`/:id` | 周列表、待分组需求、组概览与筛选 |
| 批次下 `/sub-batches`、`/reorder`、`/allocate-codes` | 建组、排序及按已保存顺序分配编码 |
| `/sub-batches/:id` 下成员、合并、拆分、更正接口 | 原子修改、版本检查和历史关联 |
| `/sub-batches/:id/sync`、`/sync-runs/:id`、`/retry` | 提交同步、逐票进度和失败恢复 |
| 货件修订、差异、补录、校验与确认接口 | 候选修订、人工决定及不可变确认 |
| 月/批次报表、导出及文件下载接口 | 同版本投影、异步生成和授权下载 |

迁移采用增量方式，保留工作区现有改动；任务入队与业务记录共同提交，文件失败沿用现有补偿机制。

## 验证与交付

- **数据库与并发：**周边界、跨月跨年、重复归组、双管理员冲突、幂等重放、过期版本、事务回滚及迁移重复执行。
- **同步与数据：**令牌续约、业务失败、分页异常、部分成功、Worker 恢复、箱身份变化、混装、跨箱、不同 FNSKU、缺值与合法零。
- **编码与文件：**P/Q 独立、超过 Z、追加保码、移除作废、合并拆分、新版本更正、生成期间版本变化，以及超过十箱。
- **端到端：**真实管理员完成导入、分组、同步、处理差异、确认编码、查看月/批次表和下载；核对页面与 XLSX 的商品、箱、数量、编码和版本。
- 执行 workspace 类型、lint、单测、构建及相关真实数据库/浏览器检查；保存脱敏证据并更新开发计划、状态、业务规则、接口及操作说明。

本次真实验证最多 **100 次业务请求**，分页、失败和重试均计数；缓存及鉴权单列统计。优先复用现有 18 票证据，补充欧洲、非 STA 和真实批次，预算耗尽保留进度。

正式 M2 验收仍需至少 20 个代表性真实货件和一个真实批次逐行签收；未覆盖类别及真实每日增量文件继续明确标待验。

## 完成后的推进顺序

先补齐 **T13 真实增量文件验收与 T22 真实批次签收**，随后推进 **T23 目标设备部署和备份恢复**。下一业务模块为 **M3 实物箱确认**，先确认 D11 的实测字段、单位、测量来源及必填条件。

本轮包含完整只读制表能力；实物核验、自动打印和领星业务写入不纳入实施。
