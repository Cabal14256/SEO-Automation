# M2/M3 流程拆分与 M4 发票及单据建设计划

> 历史建设计划。2026-10-23 起用户取消实物箱确认，新流程保留 M2 制表和 M4 发票，发票直接采用领星/M2 逐箱数据并允许本票修改；下文独立 M3 入口及发票前置确认已被[当前箱规规则](./business/invoice-box-data.md)替代。历史数据和文件继续保留。

## 一、交付目标与术语

将制表、实物核对、制作发票拆为独立任务，共用货件、商品和箱数据：

- **M2：**完成发货记录制作及导出，供现场打包使用。
- **M3：**独立完成实物箱核对，保留现有逐箱保存、整组确认规则。
- **M4：**从本周发货记录筛选完整 FBA，生成、复核和管理发票。

页面、按钮、提示和项目文档统一使用以下名称：

| 使用场景 | 统一名称 |
|---|---|
| 本期业务文件及操作 | 发票、制作发票、发票预览、发票下载 |
| 通用业务对象及管理能力 | 单据、单据资料、单据模板、单据版本 |
| 工作区入口 | 发票与单据 |

本期仍以现有模板和已填样例确定字段、布局及接收要求，输出 XLSX。术语调整不改变已确定的建设范围：

- 本周完整 FBA 可来自不同原制表组，人工确认出单范围。
- 建设可复用资料档案，支持批量导入和每票确认。
- 同构箱按范围显示，不同箱规或箱内组成逐箱显示。
- 其他发票模板、报关资料文件族、跨周选货、同一 FBA 分箱出票及外部系统写入后续扩展。

## 二、操作入口与业务流程

### M2：独立完成制表

向导调整为：

**分组与成员 → 同步与商品 → 制表确认与编码 → 发货表导出**

移除向导对 M3 状态的查询和步骤依赖。制表完成后提供“进入实物箱确认”入口，分别显示制表、实物确认和单据进度。

### M3：独立核对工作区

“发货管理”新增“实物箱确认”，按周、店铺、国家、渠道和核对状态查找原制表组。

复用现有核对组件、来源、草稿、整组确认和历史；实物箱明细导出及历史迁入该工作区，批次详情保留对应入口。

兼容旧链接与保存进度：

- 原 `physical` 标签、步骤链接和保存进度转入对应实物核对任务。
- 历史数字第 4 步继续表示发货表导出。
- 原 M2/M3 文件和确认记录保持可查询。

### M4：独立制作发票

“发货管理”新增“发票与单据”，流程为：

**选择本周货件 → 预览出单范围 → 补齐资料 → 校验 → 生成待复核发票 → 人工复核**

业务规则：

- 候选范围为本周有效制表组中的完整 FBA，包括已冻结且未被替代的组。
- 按店铺、业务渠道、目的仓与完整收件地址建议分票；主体、币种、税务或模板服务不同的继续分开。
- 地址冲突先处理，再确定出单范围。
- 可选择部分完整 FBA 出单，原制表分组、成员和箱码保留。
- 草稿可提前建立；生成待复核发票前，所有来源组必须具有当前有效的 M2 确认、箱码和 M3 整组确认。
- 页面明确展示来源组尚未完成整组核对造成的等待原因。

资料维护位于设置中的“单据资料”，支持从缺项定位到资料维护，并返回当前草稿。

## 三、数据、资料与接口

### 独立保存单据事实

新增单据、成员、来源快照、草稿修订、复核、版本依赖、模板版本和生成任务记录。

每张票绑定：

- 来源周、原制表组、稳定货件 ID、商品修订和实际箱 ID。
- M2/M3 确认及 M3 来源指纹。
- 商品申报、主体、地址、渠道和模板的具体版本。
- 每票调整内容、原因、操作人和时间。

保存草稿即保留成员。同一种单据用途下，同一货件只能被一张未取消、未被替代的票占用。取消释放占用，更正原子移交占用，重试和重新生成文件不重复占用。

### 来源整理与资料档案

从绑定 M2/M3 的原始快照回读地址、ASIN、链接等候选，校验文件哈希、店铺、FBA 和商品身份。

缺失或冲突在 M4 中显式补录并保存来源。读取页面不触发领星请求，补录不修改历史 M2/M3 确认。

建设版本化档案：

- 商品申报品名、材质、HS、用途、品牌、型号、单位、申报单价、图片及销售链接。
- 店铺主体、收件地址、渠道服务、币种、税务及必要 VAT 配置。
- 单据模板、字段映射、必填规则和下拉选项。

批量导入采用 XLSX，流程为“预检 → 展示错误和变化 → 确认提交”。历史价格、渠道和税务内容作为待确认候选；首期使用维护并确认的申报单价，未确认的最低申报比例、汇率及价格推算暂不启用。

每票调整保存为独立快照，写回公共档案需另行明确操作。

### 接口与公共契约

沿用 `/api/v1`、管理员认证、事务幂等和版本检查：

| 接口组 | 能力 |
|---|---|
| `/physical-reviews` | 分页查询实物核对任务，复用现有逐组核对接口 |
| `/documents` | 候选货件、分票预览、草稿、修订、校验、生成、复核、取消、更正及历史 |
| `/document-profiles`、`/document-templates` | 资料维护、批量导入及受控模板版本 |
| `/document-exports` | 生成任务与结果查询，下载复用现有授权文件接口 |

共享契约覆盖来源引用、成员、校验问题、状态、版本和生成结果。版本冲突返回 409，业务阻塞返回 422。

## 四、发票生成、复核与更正

### XLSX 模板适配

以现有已填 XLSX 样例建立清理后的受控单据模板，保留主表字段布局。渠道、地址库等辅助资料转为系统配置。

生成前清除旧订单、日期、地址、商品明细、数量和图片，再写入本票数据。首期按原模板将销售链接设为必填，计算在服务端完成，申报字段写入实际值。

箱明细规则：

- 整个 FBA 的全部箱完全同构时，按范围压缩。
- 同构比较完整商品身份、各商品数量、PO、重量及尺寸。
- FBA 内存在差异时，该 FBA 全部逐箱展开，使用已确认箱序。
- 范围示例：`FBAxxxx000001-6`；第 2 箱单独显示为 `FBAxxxx000002-2`，不自动增加 `U`。
- 混装箱按商品分行，同箱各行重复箱号、PO 和箱规，每行填写该商品的单箱数量。

箱数、商品数量和总重从内部逐箱事实计算；压缩后的文件必须能展开还原，并逐 FBA、逐商品对账。

### 复核与文件版本

单据按“草稿 → 待复核 → 已通过／退回 → 失效／被替代”管理，文件生成任务另存状态。

- 复核绑定具体文件哈希、单据修订、来源和资料版本。
- 调整成员、单票字段或采用新来源后创建新修订，原复核失效。
- 公共档案新增版本不覆盖旧文件；显式采用新版或引用版本被撤销时重新核对。
- 下载后在 Excel 中修改的文件，需回系统调整并重新生成后复核。
- 历史文件保留原内容，并显示当前有效性。

复用现有 Worker、文件存储和发布机制，在提交、生成和发布时复查版本。文件发布成功后沿用来源组冻结机制，失败不提前冻结。页面说明冻结作用于完整原制表组。

M2 更正使旧票来源失效时，保留其成员占用。未生成文件的草稿可显式采用当前来源；已有文件的票通过 M4 更正移交成员。取消单据不解除已发生的 M2 冻结。

## 五、实施顺序与验收

实施分四阶段：

1. **模板与契约：**固定字段映射、箱号示例、必填规则和数量对账样例。
2. **入口与数据：**拆分 M2/M3 操作入口，完成增量迁移、M4 来源及资料档案。
3. **出单链路：**完成本周选货、分票预览、草稿、校验、生成、复核和更正。
4. **验证交付：**完成自动回归、文件视觉检查、接收系统实际导入及人工签收。

重点验收：

- M2 未完成 M3 仍可导出；M3 独立恢复；旧链接、保存进度和历史文件正常。
- 原组按地址细分、跨原组同条件选货、重复成员并发提交、取消释放及更正移交。
- M3 整组等待、资料缺项、地址冲突、生成期间版本变化、失败重试及下载授权。
- 多 FBA、同构范围、混装、不同重量尺寸及超过十箱，数量和重量无遗漏、无重复。
- 接收系统识别的箱数、商品数量、PO、价格币种、图片和链接与系统一致。
- 桌面及窄屏表格、草稿恢复、键盘操作和错误提示。
- 页面、按钮、提示、导出记录和项目文档中的术语符合本计划。

上线采用增量迁移，备份和恢复覆盖新增资料、单据及文件引用。实施时新增 `docs/M4 PLAN.md`，同步调整 M3 入口说明、业务规则、API、操作手册和开发状态；实际导入或人工签收未完成的范围保留待验。
