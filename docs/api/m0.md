# M0 实际接口与恢复边界

更新：2026-10-17。以下均为当前已实现接口，前缀 `/api/v1`；账户范围已改为仅管理员。

| 方法与路径 | 权限及返回 |
| --- | --- |
| `POST /auth/sign-in/email` | 仅有效管理员可登录；错误密码 401，公开注册关闭；历史非管理员身份不能建立会话 |
| `POST /auth/sign-out` | 退出，旧会话随后失效 |
| `POST /auth/admin/create-user` | 有效管理员仅可创建管理员；创建或设为其他角色返回400/403且不落库 |
| `GET /session` | 返回有效管理员或 `user:null`；停用/非管理员/未知身份403，数据库故障503 |
| `GET /health` | 无需登录；数据库故障 503，Worker 为 `ok/stale/unknown` |
| `GET /dashboard` | 仅有效管理员；真实任务统计及数据库、Worker 状态 |
| `GET /tasks` | 仅有效管理员；最近100条示例任务及结果、错误、时间 |
| `POST /tasks` | 仅有效管理员；输入 `{label}`，成功201；未登录401，非管理员403 |

创建任务在同一 PostgreSQL 事务内保存 `demo_tasks`、`operation_audit` 和 pg-boss job，任何一步失败共同回滚。Worker 执行时重新检查提交人的当前权限；权限撤销后任务失败，并保留可查询错误。

API、Worker 为独立进程。当前 M0 采用 `retryLimit=0`：排队任务跨重启继续消费；已完成任务保留原结果与完成时间；领取后进程被强杀，未提交业务事务回滚，队列超时后转为失败，由任务/工作台查询对账回应用记录。普通队列超时 900 秒；自动重试、逐项续跑及外部结果未知回查尚未实现。

文件当前通过服务端 `saveBusinessFile` 写入受控私有目录，保存不可变文件、SHA-256、大小和数据库索引；索引失败清理已发布文件。默认开发文件根为被 Git 忽略的 `.local/development/data`，原有合法项目外目录仍受支持。M0 没有开放上传下载 HTTP 接口。通用业务任务、逐项结果、业务幂等键和授权文件接口随 M1/M2 实际业务切片补齐，不能直接把示例任务作为领星或文件生成生产任务使用。

故障响应只返回固定错误码；服务端日志只保留固定事件与经过校验的错误码，数据库连接串、SQL 参数、密码和会话不进入日志。业务显示、数据库会话统一 `Asia/Shanghai`，持久时间戳仍为带时区时间。
