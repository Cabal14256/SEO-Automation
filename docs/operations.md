# 运行与维护说明

## 月内发货次操作（2026-10-24）

发货时间统一显示“某月第几次”，需求、发货、报表及制作发票入口取消周选择。不同周或月份导入的需求可一起安排，首次业务日期保留为来源事实。人工建立与自动导入共用月计数器；人工选择编号日期及首票需求，整次建立成功才领取次数，之后手动同步与核对，不会因创建而访问领星。

选择已有发货次可增加新票或向兼容组追加需求，原票号、成员顺序和已分配箱码保留。整次导出成功冻结成员安排；修改前发起“发货次更正”，填写原因，保存原安排快照并沿用原月份、次数、日期及票号。冻结内部组仍需独立更正，旧文件不回改。历史未关联组显示“未关联发货次”，未冻结组可人工显式关联；不得按旧周自动补号。

发票候选按发货次读取完整 FBA，同一次发货内不同导入周不再阻塞。旧发票和后续业务保留历史快照；业务关联和重复占用按实际货件、内部箱及来源版本核对。

接收差异提示自 2026-10-24 起仅在领星货件状态 `CLOSED`（接收完成）且有效接收数与原申报数不同的时候显示。未接收、接收中及状态未知均不提示；已存的旧提醒也按此规则显示，无需为清提示修改准备量或装箱。接收数和申报数保持独立，接收完成后有差异仍可制表。历史快照未保存状态时先不提示，后续重新同步后按取得的状态判断。已冻结行仅从最新同身份领星候选读取接收状态和接收数，用于与原冻结申报量比较；不会采用未确认候选的准备量或箱数据，原确认和已生成文件不改写。

## 当前发票箱规操作（2026-10-23）

实物箱确认已从工作区移除。完成 M2 数量、箱关系、箱序和箱码校验后，直接建立发票；系统从绑定的领星逐箱快照带入 PO、KG 毛重和 CM 长宽高。在“单票资料 → 逐箱制单资料”按箱修改，保存资料修订后再校验与生成。自动来源与最终采用值并列展示，人工修改只作用于本票；每箱“恢复自动值”移除该箱全部覆盖，点击后仍须保存资料修订。显式清空会作为缺值阻塞生成。来源缺值或未知单位可在本票填入有效值；箱身份及数量问题仍须回 M2 处理。

已有文件通过“更正”修改箱规，重新生成并复核；旧文件和历史保持原内容。发票及后续工作流采用同一最终逐箱值，物流回收重量、计费重和报关毛净重等独立事实仍按各模块填写。重新打开读取已保存修订；显式采用更新来源保留相同内部箱 ID 的人工覆盖，已移出本票箱的覆盖会移除。详细取值及兼容规则见[发票箱规](./business/invoice-box-data.md)。

此次调整不删除旧 M3 表、确认、实物 XLSX、任务或历史引用；备份与归档继续保留并校验这些材料。恢复验证兼容没有 M3 引用的新发票，以及有 M3 引用的历史发票；历史引用仍须实际存在。下文旧 M3 操作只作历史兼容参考，不是当前发票的生成门槛。

## M5–M8 使用与升级（2026-10-22）

先备份数据库和 DATA_DIR，停止旧 API/Worker，执行 `corepack pnpm db:migrate` 应用 `0017_flashy_surge`，再启动新版本。迁移只增加工作流表，不认定旧批次完成。新增队列 `workflow-file-export` 由独立 Worker 处理。

先准备领星单据并登记库存分配结果，回收物流订单、箱唛和重量，完成线下出货复核后放行。实际已交但条件不全时填写异常原因保留事实。报关和9810分别绑定提交文件及反馈；费用按外部单号核对，补账／退款追加行后重新结清。批次归档页实时展示阻塞项；成功且依赖有效的 ZIP 才显示已归档。历史包保留但不能替代新确认。详见 [M5–M8 说明](./m5-m8-implementation.md)。

## 自动确认与编码（2026-10-20）

按本次操作变更，“校验、确认与编码”不再要求填写确认说明或重复勾选。进入该阶段后，同步状态已读取成功、同步已结束、当前成员和商品箱版本齐备且无阻塞异常时，系统自动确认并分配全部箱码；页面显示版本、时间及已保存箱码后可继续导出。接收量差异等提示不阻止，身份、数量守恒、箱映射和箱序等阻塞仍需先处理。该确认是制表确认，实物核验保持独立。

系统自动记录操作说明、当前管理员和时间，确认与分码使用同一数据库事务。已有有效确认及箱码不重复建立；追加保留旧码，新箱接续，冻结组仍通过更正处理。请求结果未知时使用“重试自动确认与编码”重放原请求；刷新也保留原操作号及版本，不创建新操作。已知版本或校验冲突会暂停，点击“刷新后重新校验”读取当前事实再继续。

## 发货工作台整合（2026-10-20）

2026-10-23 增加货件需求管理：“新增需求”打开在线填写，完成原有解析和确认后正式提交；也可继续导入文件。每票提供查看、编辑及删除入口，商品和逐箱视图中每票仅显示一套。编辑仅调整渠道、目的仓、地址、参考数量、来源填写时间和备注，保留店铺、FBA及首次业务日期；已分组需求的渠道在分组流程核对。修改后产生新需求版本，候选及批次确认需重新核对。删除须填写原因，会取消需求、移出当前批次并保留来源、版本及操作历史，切换“需求记录状态 → 已删除需求”查询；后续导入不会自动恢复。已冻结、有效下游单据／业务引用及运行中同步／导出阻止直接编辑或删除，按详情说明先处理下游或发起更正。网络异常可保持内容原样重试；版本冲突先显式重新读取并核对最新内容。

“发货管理 → 发货工作台”使用一套发货主表，不再区分需求处理与发货成品标签。顶部统一发货月份、发货次、店铺、国家、渠道、状态、区域及关键词筛选；左侧选择全部发货、待分组需求或具体批次。展示方式提供货件分组、商品平铺、逐箱长表，使用同一明细响应、同一货件分页和来源版本；货件分组在新范围默认展开商品，刷新同范围保留手动折叠。选择具体批次后，店铺／国家／渠道放在批次摘要，表内保留货件及商品明细，避免重复展示相同批次信息。

主表覆盖未同步、候选、待核对、已确认和已冻结货件。有效确认及冻结货件展示确认快照，确认失效后展示候选并提示核对；批次总量／本月数量仅来自有效确认，候选返回空值。逐箱数量、重量和尺寸保留实际箱身份及来源单位，不用缺失值冒充零。已安排货件按发货次编号日期归月；未安排需求的首次业务日期只用于来源查询。商品或编码命中保留整票商品；导出勾选按完整批次执行，提交组版本和确认引用，并在成功发布后冻结。

“安排货件”选择仅用于建立或加入批次；“导出此批次”及“选择本页可导出批次”使用独立选择集，每次最多500组。候选、确认失效或缺少箱码的批次不能导出；页面行与资格接口版本不一致、任一读取失败或筛选未应用时禁用导出并提示重新核对。切换展示方式保留两类选择及分页，变更筛选或批次范围清空旧选择。统一操作栏提供导入、草稿箱、导入记录、生成XLSX、导出记录及刷新。

导入结果选择“新建发货批次”或“加入已有批次”，也可稍后分组。需求池支持按 `demandId` 去重多选，最多1000票；不同周或月份导入的需求可安排到同一次发货，同店铺、同国家和同渠道组成一个内部处理范围。多个范围须人工选择其中一个，其余保留在待分组池。已有归属的需求打开原批次处理，不随重复导入迁移。

新建继续经过成员、名称和当前版本核对。加入已有批次仅列出同范围未冻结组，提交保留原有全部成员及需求版本，追加后重新制表确认。结果未知时锁住原请求，并保留相同操作号、成员和版本；重试原加入请求后才能继续。当前浏览器刷新可恢复未决追加请求，已知版本冲突需刷新范围重新核对。冻结组继续通过原详情发起更正。

创建或加入完成后可直接继续同步与核对。发票与单据保持独立入口，旧 `/imports`、`/batches` 和批次详情/处理链接继续可用；`/batch-reports`、`view=reports` 进入同一工作台，初始按商品平铺。发布需同时更新契约、API和前端。技术回归为 `corepack pnpm shipping:browser`，可单独运行 `shipping:workbench:browser`，使用独立内存HTTP夹具、不调用领星；旧双标签和独立成品表脚本保留历史断言，以显式legacy参数运行。

## M2 与发票操作（2026-10-23 更新）

“发票与单据”的单据记录支持搜索名称、编号、订单号、FBA 或店铺，并与状态、发货次组合查询；点击搜索或回车生效，重置回到当前单据第一页。“制作发票”新增草稿；列表可直接查看、编辑草稿，已生成单据通过更正保留原文件。删除须填写原因，会标记为已取消并释放货件占用；历史和已生成文件保留，可切换“已取消”查询，原制表组冻结不解除。生成任务进行中不可删除。删除失败保留原因，网络异常原样重试；版本冲突先重新读取目标并核对，再确认删除。

发货管理提供发货工作台和发票与单据两个入口；`view=demands|batches|reports` 均进入单表工作台，`batches`兼容上次批次处理恢复，发票使用 `view=documents`。旧 `view=physical` 及批次 physical 深链接转入发票与单据，批次详情不再显示实物确认标签。M2 处理向导为分组、同步、制表确认、发货表导出四步，发货表只检查自身条件；旧数字第 4 步恢复到导出。新流程不再进入逐箱实物核对或整组确认。

在设置的“单据资料”维护商品申报、主体、地址、渠道和税务配置。商品以完整 `sid + msku + fnsku + sku` 匹配，维护品名、材质、海关编码、用途、品牌、型号、销售链接及图片。新票在资料步骤查询并采用领星 Listing 普通售价，申报单价自动计算为售价的 20%，四舍五入两位，无需勾选确认；旧手工单价仅供历史规则使用。每个货箱编号只输出一个固定排序的代表产品，默认申报数量取其箱规件数，箱规缺失则用全箱实际数量合计。请核对混装及数量差异提醒，必要时导出后在 Excel 修改，系统实际发货数量不随之变化。主体绑定店铺，地址绑定目的仓，渠道绑定业务渠道及服务，税务绑定目的国家。资料修改建立新版本。

批量维护时先下载系统 XLSX 模板，填写类别、稳定资料键、预期版本和相关字段，再“预检导入”。已有资料须填写当前预期版本；空白字段会移除原值，应核对变化列表。预检不会修改资料，核对全部错误和差异后确认提交；提交前版本变化则整批拒绝并提示重新预检。图片可在商品资料页面上传 PNG/JPEG，避免在表格中手工复制大段 Base64。

在单据资料页面上传受控丰信 XLSX 模板，服务端检查整套主表字段，清理旧订单、地址、商品、图片及附表后保存不可变版本。旧 `.xls` 是核对依据；上传文件使用 `.xlsx`。模板和业务文件保存在受控私有 `DATA_DIR`，不得复制到前端 `public` 或 `dist`。

在“发票与单据”选择本次发货的完整 FBA，分票预览按店铺、业务渠道、目的仓和地址拆分，可跨原制表组选择。不同主体、币种、税务或模板须分别建票。同用途货件只能有一张有效占用单据。建立草稿后采用所需资料和模板版本，检查箱规并填写交货仓站等资料；备注与亚马逊预约配送时段可留空。来源地址有冲突时查看候选，明确选择并记录确认原因。缺项草稿可以保存、离开并继续。

制作和继续单据使用四步弹窗向导：“货件与来源 → 单票资料 → 校验与生成 → 文件与复核”。第一步新建时选择完整 FBA 并预览分票，已有单据可查看来源、显式采用来源或建立更正；保存草稿后进入资料步骤。领星补齐、地址采用、商品申报和模板版本统一放在资料步骤。翻步不会自动保存、生成或复核，生成和复核继续使用各自明确的操作按钮。

同一页面中翻步、暂时关闭并继续向导保留当前输入；隐藏工作区关闭弹窗并暂停单据轮询。已保存单据的步骤按账号和单据保存在当前标签页，刷新后重新读取服务端版本；未提交输入不承诺刷新恢复，应先保存资料修订。切换其他单据或离开页面时，未保存修改需明确处理；提交进行中不能关闭向导或切换步骤。

生成前先保存并校验。有效 M2 确认、箱码、完整有效的最终逐箱 PO/毛重/长宽高及申报资料是生成门槛；422 表示业务缺项，409 表示版本冲突，应刷新并重新核对。任务排队或运行中保留原操作编号重试；已发布文件的草稿不可原地改写，应建立更正。Worker 生成期间重复检查来源、资料及模板，文件成功发布后才冻结来源组。即便单据只选择组内部分 FBA，冻结仍作用于其来源 M2 组。

生成文件先标为待复核。下载后核对文件、逐 FBA/商品箱数、数量、总重及图片，再通过或退回，复核记录绑定具体文件 ID、SHA-256 和依赖版本。源数据或采用的资料/模板失效后，已通过的复核也显示失效；历史文件仍可追溯。取消释放用途占用，更正原子地转交原票货件占用，原票、修订、校验、任务和复核历史保留。下载需要管理员会话。

升级前备份数据库和 `DATA_DIR`，执行增量迁移至 `0015`，重新构建并启动 API 与 Worker；新增生成任务名为 `document-invoice-export`。整库备份覆盖新增资料、模板、单据、占用、修订、复核及任务表，文件校验覆盖模板和发票索引、哈希及来源引用。恢复后保持外部请求关闭，先核对未决任务及引用，再按部署说明恢复服务。

## 发货管理工作区（2026-10-18）

侧栏“发货管理”可展开或收起，下设发货工作台、发票与单据两个子项。工作台内容区统一主表，地址参数 `view=demands|batches|reports` 均高亮同一工作台子项，旧详情链接也会高亮工作台。收起父菜单不改变当前页面；侧栏折叠时点击“发货管理”图标展开侧栏和子项，键盘焦点留在父菜单。手机端打开业务菜单后选择子项，选中后关闭菜单。

各视图沿用筛选、操作栏、列表和原向导。同一工作区内切换和浏览器前进/后退保留已访问视图的筛选及同页表单草稿；隐藏视图关闭其原生弹窗并暂停轮询，返回后恢复原步骤。

发货管理内容区随右侧可用空间伸展，保留正常页边距，统一主表在内部横向滚动。月份、区域等条件通过“筛选”应用，“重置”恢复全部；货件分组、商品平铺和逐箱长表只改变展示。操作栏生成所选完整批次的XLSX，“导出记录”打开下载小窗口；导出仍绑定已应用身份范围和当前确认版本，原冻结规则不变。

导入、批次、成品表的原地址以及详情、新建、处理向导深链接继续可用。完成导入或批次处理后返回工作区对应视图。进入详情、设置、工作台或刷新页面会重新挂载工作区；需求导入按下述 2026-10-19 草稿箱规则显式恢复，批次向导仍按其各自规则处理。

桌面“设置”位于侧栏底部，折叠时显示齿轮及提示；手机端位于顶栏账户区。店铺映射仍通过 `/settings/seller-mappings` 维护。

运行 `corepack pnpm shipping:browser` 可使用独立 Vite 和内存API夹具检查导入安排、统一主表、当前导航与导出，不需要真实账号、数据库或领星服务。旧独立实物表的兼容回归与历史证据单独保留。

## 需求导入向导（2026-10-18）

在 `/imports` 点击“导入”，文件上传与网页在线表格共用同一向导。在线表格指在本页面填写或粘贴需求，不是连接飞书在线文档。导入记录小窗及 `/imports/$importId` 详情中的“继续导入”均可恢复已有导入；详情继续保留原件、源行、解析版本、需求版本与提交来源。

1. **选择方式**：选择表格文件或在线表格，再进入填写。已有导入保持原来源；更换内容使用“新建导入”。
2. **填写与解析**：可先点击“下载模板”，填写数据页并保留表头；选择有效 `.xlsx` 后自动上传并校验，无需再点击上传按钮。服务端检查工作簿结构、表头和非空需求行，唯一可用工作表通过后自动解析，无需再点击解析按钮；格式错误、损坏文件和空模板直接显示原因。多张可用工作表或只有隐藏候选时，在本步选择工作表及映射后继续。在线填写或粘贴后点击“提交并自动解析”才接收并解析。核对源行与错误，源行读取成功后点击“下一步：确认店铺”；行内错误保留定位，其它有效需求可继续后续提交。
3. **确认店铺**：确认来源名称对应的店铺与国家，至少确认一个有效店铺后点击“生成差异预览”。成功生成后才进入下一步；未确认店铺的源行保留为错误，不阻止其他有效票后续提交。
4. **核对与提交**：查看新增、相同、变化、错误、冲突和来源缺失项，选择本次范围；变化项须逐票确认，错误和冲突不能提交。生成预览或提交期间暂时锁定步骤切换；成功提交后进入结果页。
5. **导入结果**：查看本次操作对应的结果和来源，使用“继续处理剩余需求”处理未提交的有效项及错误/冲突，或返回需求列表、新建导入。“有效项已提交”不代表错误行已消除。

### 选择文件后自动上传（2026-10-19）

只有当前活动向导处于“表格文件导入”的“填写与解析”阶段，选择文件后才自动上传。取消文件选择不触发上传；非 `.xlsx`、空文件或超过 10 MiB 的文件先在本地提示，不发送上传请求。上传期间显示进度并暂时锁定文件和步骤切换，成功后继续自动解析和源行核对，正常流程没有“上传并校验”按钮。

上传或校验失败后保留所选文件、错误说明和原操作号，显示“重试上传”。点击后使用同一文件及操作号重试，不因重渲染或切换步骤反复发送同一自动请求；若文件需修改，修正后重新选择。服务端的同请求重放和相同文件去重规则保持不变。

从草稿箱恢复尚未接收的文件草稿后，进入文件的“填写与解析”阶段会自动继续原文件及原上传操作号。恢复到第一步时，须进入第二步才触发；已接收导入只读取解析结果，不重新上传原件。在线草稿即使同时保存了另一输入分支的文件，也不会在在线方式或隐藏阶段上传该文件；只有主动切到文件填写阶段才继续。保存草稿本身仍不发送上传请求，也不正式提交需求。

### 需求导入草稿箱（2026-10-19）

每次点击“导入”或“新建导入”都从空白开始。此前自动从本标签页 `sessionStorage` 恢复上次导入的行为由本节覆盖；本地暂存不再作为自动继续上次工作的入口。需要续做时，主动打开“草稿箱”并选择“继续编辑”，或从“导入记录”继续已接收的导入。

填写中点击“保存到草稿箱”，或在有未完成内容时关闭向导、新建另一导入或离开页面，会提示“保存到草稿箱？”。填写草稿名称后可选“保存草稿并退出”“不保存，退出”或“继续填写”。保存成功后退出本次向导；已知校验失败保留当前输入供修改，编辑的草稿已在其他窗口变化时可“另存新草稿并退出”，不覆盖对方版本。网络中断或响应无法确认草稿保存结果时，冻结原草稿 ID、内容及期望版本，使用“重试原草稿保存”核对原请求，结果确认前不更换内容或另建草稿。

草稿保存在服务端并按当前账号隔离，保存标题、在线行和查询日期、所选文件内容，以及已接收导入的 ID、阶段和必要的提交恢复标识。管理员可以把有权访问的已有导入关联到自己的草稿，草稿仍仅自己可见。文件最多 10 MiB、在线最多 1000 行；保存草稿不是上传或正式提交，不建立需求或业务日期。重新打开后仍要读取当前目录、解析和需求版本，过期预览、普通勾选及变化确认不能作为跳过核对的依据。草稿箱支持名称或 FBA 搜索、重命名和删除；删除草稿保留已接收导入和已提交需求。

浏览器刷新、关闭标签页或关闭浏览器由原生 `beforeunload` 提醒约束，提醒是否出现及文案由浏览器决定。网页不能保证此时打开自定义保存窗口或完成异步保存；要保留内容，先取消浏览器离开，再在系统内点击“保存到草稿箱”。直接确认离开、进程被终止或浏览器崩溃时，未显式保存的输入不保证可恢复。

| 内容 | 当前恢复边界 |
| --- | --- |
| 已成功接收、已有导入 ID 的内容 | 原件/在线快照、解析、预览和提交结果保存在服务端；从导入记录、详情或关联草稿继续，重新检查版本。 |
| 尚未提交的在线单元格及尚未上传的文件 | 显式保存到草稿箱后可继续；选择“不保存，退出”会放弃本次未保存输入。 |
| 普通页面勾选、尚未生成预览的店铺选择 | 恢复后重新核对；不承诺把普通勾选当作持久确认。 |
| 已发起而结果未知的业务提交 | 原 payload、`previewId`、选择范围和 `operationId` 用于原请求恢复；先重试原提交或核对提交记录，不能把未知结果当作已知失败。 |

草稿 API 和并发保存规则见[需求导入契约](./api/imports.md#导入草稿箱2026-10-19)。当前头程业务渠道仍由人工填写；领星发货单渠道的官方 API [调研已完成](./integrations/fba-logistics-channel.md)，尚未接入在线补全，不自动调用这些接口。

### 关闭、刷新与恢复（2026-10-18 历史）

以下为 T25 交付时的恢复边界及其验证记录。当前需求导入的空白新建、草稿保存和主动恢复以上一节为准，旧 `sessionStorage` 自动恢复说明不再作为当前操作规则。

| 内容 | 恢复边界 |
| --- | --- |
| 已成功接收、已有导入 ID 的内容 | 原件/在线快照、解析、预览和提交结果保存在服务端；同一登录用户、同一浏览器标签页用 `sessionStorage` 保存导入 ID、阶段与核对版本。可从导入记录或详情继续；本地进度不可用时重新读取服务端状态。 |
| 尚未保存的在线单元格及尚未上传的 `File` | 仅在当前页面、同一向导实例中关闭后重开保留；刷新、离开页面或新建导入后须重新填写或选择文件，不承诺持久草稿。 |
| 普通页面勾选 | 当前向导内跨页保留；刷新后重新核对选择。已发起而结果未知的提交范围另外保存原始 ID 集合，用于恢复原请求。 |

也可使用 `/imports/new?importId=<导入UUID>&step=4` 打开已有导入，`step` 支持 `1` 至 `5`。这是恢复目标，实际步骤仍受解析完成、源行核对及有效预览约束，不能靠 URL 跳过前置检查。来源、店铺、预览或提交记录读取失败会显示重试入口，不把读取失败当成没有历史数据。

当时上传和校验期间暂时锁定步骤及来源切换，网络异常时通过“上传并校验”重试；2026-10-19 起改为选择有效文件后自动上传，仅失败后显示“重试上传”，具体以上节当前规则为准。模板文件仍为 `需求导入模板.xlsx`，包含空白数据页和独立填写说明；不含示例需求。表内“元数据来源”和“查询时间”是保留列，不需要手工填写；模板中的参考数量不作为正式商品数量。

网络中断、响应不可识别或服务端结果未确认时，先点击“重试原提交”或“核对提交记录”。系统冻结原 `previewId`、选中项、变化确认项和 `operationId`；重试使用相同 payload，不因目录或解析更新自动换成新请求。记录中找到同一操作后恢复结果并清除待确认请求。已知版本冲突保留选择和反馈，返回确认店铺并重新生成差异；不要把未知结果直接解释为失败后另行提交。

其他窗口重新解析后，已核对的旧源行版本会失效。点击“核对最新解析版本”，回第二步读取并核对新源行，之后才能生成新预览或普通提交；历史解析仍不可新提交。恢复原未知提交属于原请求重放，保留其原始内容与操作编号。

## 设置与店铺映射（2026-10-18）

侧栏、折叠侧栏和手机导航的主入口为“设置”。`/settings` 进入 `/settings/seller-mappings`，设置页内使用“店铺映射”子导航；目前仅提供已实现的店铺功能。旧深链接继续可用。

主页面按筛选条件、操作栏和店铺大列表组织，可搜索店铺名称、别名或 sid，并按当前来源的有效状态筛选。点击“来源设置”“新增人工店铺”或行内“维护别名/维护映射”分别打开原生小窗口；来源切换与显式同步在“店铺来源设置”窗口完成，别名编辑和版本历史放在“维护店铺”窗口中。人工新增仅在人工来源下开放，保存后继续核对该人工店铺。

领星来源中，已有可信授权缓存及后续显式同步取得的有效授权店铺自动批准，无需逐店点击批准。自动批准与本地停用分别保存，人工资料的待确认/已批准/已停用状态保持独立；本地明确停用不会被同步恢复。未授权或已移出当前目录的店铺不可用于该来源下的导入。查看、搜索、翻页、刷新目录或打开小窗口只读取本地数据，不执行批准回写，也不请求领星；只有明确点击同步按钮才查询外部目录。

领星“维护别名”只修改本地别名及停用/恢复决定，必须填写原因，不提供“待确认”状态，也不需要首次批准勾选。人工维护的首次批准规则不变：当前为待确认且该人工资料历史从未批准时，可勾选“已核对店铺身份”代替手写原因；后续修改、重新批准和停用均需原因。官方名和别名发生跨店碰撞时继续人工确认，不自动选取 sid。全局目录自动批准不代替本次导入的店铺、源行和差异确认。

## 发货批次工作区与向导（2026-10-18）

`/batches` 按筛选条件、操作栏和批次大列表组织。默认显示全部月份；可按发货月份、发货次、店铺、国家、业务渠道、处理状态以及批次名称/FBA 搜索，点击“筛选”生效。列表按服务端分页，每页 20 项；一行对应一个有效人工子批次，已建立但无有效组的处理容器保留占位。列展示名称、发货次、店铺、国家/渠道、货件数、同步进度、状态、更新时间及操作。已建组即使尚无可导出的确认数据，也能进入处理向导；“已有数据”或“已确认”不代替正式导出的版本校验。

### 新建发货批次

从“新建批次”、待安排需求，或 `/batches/new` 进入四步向导：

1. **选择发货次**：选择已有“某月第几次发货”，或填写编号日期建立新发货次。新发货次在首票及内部组成功建立时原子分配月内次数，不建立空发货次。
2. **选择需求**：手动选择未分组货件；店铺 `sid`、国家和业务渠道须一致。搜索和筛选切换保留已选项，不依据相同商品、日期或配方自动合组。
3. **核对与建立**：核对发货次、成员和需求版本，填写名称、建立说明并勾选确认。发货次或需求变化、成员已被他人分组、已知 409 均须返回选择重新核对，名称和选择保留。
4. **建立结果**：分组保存后可“继续同步与核对”，或显式新建另一批次。建立分组不会自动同步、确认、分配编码或导出。

创建草稿按登录用户和发货次入口保存在当前标签页的 `sessionStorage`，通用新建使用独立作用域，包括选择、名称及待确认的原请求。网络断开或响应无法识别时，“重试原建立请求”复用完整原 payload 与 `operationId`；结果未知期间锁住修改和步骤切换。刷新后仍可重放原请求，避免再次建立。已知 409 按新版本重新核对，不能把未知结果当作已知失败而改成另一请求。

### 处理已有批次

列表“处理向导”和详情“打开处理向导”进入下列四步，首次进入按当前已同步、确认与编码状态选择可处理阶段；已保存步骤仍受当前版本门禁约束。

1. **分组与成员**：追加/移除、移动、拆分或合并均由人员选择，并记录原因和版本。冻结或被替代组保留历史，通过独立更正组处理变更。
2. **同步与商品**：查看候选、商品与逐箱数据，按需人工补录或更正。只有点击“同步全部成员”或“仅重试失败票”才发起领星只读任务；打开、刷新、恢复、切换步骤和建立分组只读取已有本地状态。同步中或同步状态读取失败时不能进入普通确认/导出；失败票与请求预算按原规则显式恢复。
3. **校验、确认与编码**：当前成员均须有对应需求版本的候选；处理阻塞异常、校验数量与箱序后，系统自动确认当前版本并分配箱码，无需填写说明或勾选。成员/候选更新使旧确认失效，重新校验通过后采用新版本；未知请求先重试原操作，不能用保存的步骤绕过。
4. **成品与导出**：当前确认有效且所有箱已编码后才能生成所选范围 XLSX。状态变化使条件失效时保留页面并停用导出，返回核对；冻结组继续使用原确认快照和旧文件。

“来源与登记”提供来源追溯、实际发货日期、打印登记和更正入口；“查看批次详情”保留原有详情、标签页与历史操作。自动刷新失败时，已有阶段与未保存内容保持在页面中，写入暂时停用，重试成功后继续。

同一页面、同一组的阶段切换及关闭重开保留已访问表单。处理目标和阶段按用户/组保存到当前标签页，刷新后恢复目标与步骤，再读取服务端版本；处理表单中未提交的字段仅同页保留，不承诺刷新后恢复。新建入口优先进入创建向导，避免旧处理进度同时打开第二个小窗。

处理深链接为 `/batches/<处理容器UUID>?groupId=<子批次UUID>&wizard=process`；原 `/batches/<处理容器UUID>?groupId=...&tab=confirmation&demandId=...` 继续打开详情。进入更正组同步更新深链，刷新后仍指向新组；处理容器/组不匹配时停用操作并提供“打开所属处理批次”。列表中打开处理向导保留原列表筛选，完成后返回列表。

独立 UI 验证使用内存 fixtures，不连接数据库或领星：

```powershell
node scripts/t26/settings-browser.mjs
node scripts/t26/batches-workspace-browser.mjs
```

## 数据与恢复

业务文件写入 `DATA_DIR`，索引与哈希存在数据库。每日将数据库、`DATA_DIR`、`.env` 的受控副本、模板、迁移和应用版本备份到独立介质；至少保留最近 30 天每日备份。每月在独立环境恢复一次并核对文件哈希、任务、操作记录及账号登录。

恢复时先停止 Worker，检查未决任务及外部操作，再允许继续执行。M0 示例任务不访问外部系统。排队任务重启后继续执行；已经完成的结果保留。当前队列 `retryLimit=0`，已领取后强制中断的任务在超时后转失败（普通任务默认 900 秒），查询接口对账回写失败状态，不自动续跑或重放。验收将单个故障任务超时缩为 2 秒，未改变普通队列策略。后续业务任务的逐项续跑、幂等及未知结果回查需在接入业务时实现。

日志中不得输出数据库密码、认证密钥、业务附件内容或完整个人信息。业务日期和发货次编号日期按 `Asia/Shanghai` 解释；数据库保留带时区时间戳。发货次以稳定 UUID 标识，按编号日期所在月及月内次数展示；旧周日期仅作兼容来源元数据。

## 业务数据运行约束

- 一次发货可包含多个业务票及内部组；人工分组必须明确选择发货次，自动分票按来源空白行及店铺/国家/渠道形成内部组。
- 子批次默认按最小标准化 FBA 号排序，人工调整需记录排序版本。
- 已确认子批次允许追加 FBA，追加后创建新数据版本并重新校验；已确认或已导出的旧编码不重排。
- 人工合并、拆分、移除、重复处理和数量修改均写入操作审计。移除 FBA 后旧箱编码作废。
- 已导出或已打印的子批次禁止直接移动、合并、拆分和追加；更正使用新版本。
- 领星同步保留原始响应快照、请求哈希、分页游标、错误码和任务状态。异常子批次不得正式导出。

## 历史兼容：M3 实物箱核对操作（2026-10-18）

本节仅记录旧功能及历史维护方式。2026-10-23 起工作区不再提供该操作，当前发票使用本页顶部的箱规流程；旧文件、确认和备份仍保留，不据此要求新业务补做实物箱确认。

发货处理向导为“分组与成员 → 同步与商品 → 制表确认与编码 → 实物箱确认 → 成品与导出”，详情增加`physical`入口，沿用已有工作区、表格、小窗口及窄屏滚动风格。旧数字第4步恢复为成品与导出，不误认成新增实物步骤；跳过M3不会显示其已完成，原发货表仍按M2条件导出。

1. 先确认M2商品和逐箱关系并分配全部箱码。进入实物箱确认只读取已有可信证据，先核对并采用来源；没有可信历史快照、领星缺项或需更新时，再明确日期范围与请求预算点击实物同步。M3同步不发布M2候选，不自动写领星。
2. 一箱一行核对登记毛重、箱规、PO和商品。采用值为KG/CM两位数；一致仅勾选，有差异填写实际不同的测量项与原因，领星值仍是最终采用值。必要重量尺寸、单位或Reference缺失／冲突须回领星处理后同步，身份／商品／数量变化回M2映射或更正。
3. 保存草稿后可刷新、退出或换电脑恢复；未保存输入只存当前标签页。后台刷新或409不覆盖输入，按提示核对新版本后重新载入。全部箱完成并保存后，再确认整组。
4. 批量处理先下载本组模板，仅编辑核对结果、实测值及原因；上传预检后明确提交同一文件。文件、只读来源列、箱身份或版本变化均拒绝整批提交，不会部分覆盖。
