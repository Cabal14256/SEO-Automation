# 领星单据资料查询与权限

新建发票先在第一步多选完整货件，再到第二步填写本次公共出单资料（可选）。两步之间返回或暂时关闭后继续会保留输入，第一步的下一步不建立任务；仅第二步“自动生成发票”启动后台处理。服务端逐范围查询商品在领星维护的申报资料、普通售价及箱规件数，并采用服务端归档预览。整批统一检查，缺项集中在一页补齐；允许部分保存，但全部范围通过前不生成部分文件。最终输出一份 XLSX，相同表头合为同一 Sheet，不同地址或币种等表头分 Sheet。任务在浏览器关闭后继续运行，无须逐票点击查询、校验和生成。旧单据详情仍可查看来源和历史文件。查询只读取领星数据；采用在本系统保存来源和新修订，其他申报资料补充空白，售价和箱规来源快照按本次查询替换，查询缺值不会保留旧值冒充本次结果。

2026-10-24 起，新票使用 v2：申报单价按有效售价 `× 20%`，精确计算后 `ROUND_HALF_UP` 保留两位，无需勾选价格确认。有效 Listing 普通 `price` 始终优先；仅售价缺失或无效时，可在统一补充页或本票资料中填写实际商品售价及真实依据，币种锁定为本票国家币种，不允许直接改申报单价或换汇。箱规件数取产品详情 `cg_box_pcs`，缺失时按全箱实际数量合计。每箱仅输出固定排序的首个代表商品。原领星售价和箱规归档保存在只读 `productSourceFacts`，人工售价另存服务端审计记录，不覆盖原件；旧手工申报价、清关价、报关价不用于 v2。下文国家清关价及人工价格确认说明仅保留为 v1 历史规则。

人工补充要求已有可核验的领星归档及完整 sid/MSKU/FNSKU/SKU 身份。旧归档售价为空时不因 `LISTING_PRICE_INVALID` 标记单独要求重查；已知原件中有有效金额则仍禁止人工替代，币种冲突须另行处理。售价和不超过 1000 字的依据须同次提交，系统记录填写人、时间、国家币种、归档哈希和成员来源版本；相同身份/币种可跨单据合并填写，不同币种分开。售价保留原精度，如 `19.99 → 4.00`、`0.025 → 0.01`；人工 `0.01` 因申报价舍入为零不接受。补充仅用于本票，不修改领星或公共档案，未完成补充前仍阻止整批输出。

## 本次新增权限

在当前 App 对应的领星开放平台 API 权限中开通下列查询接口，并确认应用有权访问本票所属店铺和产品。

| 官方接口名称 | 方法和路径 | 用途 |
|---|---|---|
| 查询亚马逊 Listing | `POST /erp/sc/data/mws/listing` | 按 sid 与 seller_sku 精确查询普通 price、currency_code，核验 FNSKU 和本地 SKU |
| 查询FBA商品信息列表 | `POST /erp/sc/routing/fba/shipment/getFbaProductList` | 核对 sid、MSKU、FNSKU、SKU，取得本地产品 ID、图片、销售链接 |
| 查询本地产品详情 | `POST /erp/sc/routing/data/local_inventory/productInfo` | 读取申报品名、HS、材质、用途、品牌、型号、单位、cg_box_pcs 箱规件数、图片及特殊属性 |
| 主体列表查询 | `POST /basicOpen/stockSubject/list` | 展示有效主体候选名称；不自动确定本票卖方主体 |

商品申报资料、售价和箱规完整补全涉及上表三个商品查询权限。主体查询独立执行；主体权限未开通时仍可展示已经成功取得的商品资料。主体列表只提供主体标识、名称、类型、状态等信息，不能补齐主体地址或 VAT。

2026-10-20 本地账号定向只读验证：FBA 商品信息列表返回 HTTP 200 / 业务码 0；本地产品详情、主体列表分别返回 HTTP 200 / 业务码 403。当前需申请后两个接口权限。该结果仅表示当次应用和账号状态，开通后应重新查询核验。

官方文档：[FBA 商品信息](https://apidoc.lingxing.com/new/api-docs/FBA/GetFbaProductList/)、[本地产品详情](https://apidoc.lingxing.com/new/api-docs/Product/ProductDetails/)、[主体列表](https://apidoc.lingxing.com/new/api-docs/BasicData/StockSubjectList/)。

| 官方接口名称 | 方法和路径 |

| 查询货件列表 | `POST /erp/sc/data/fba_report/shipmentList` |
| 查询货件详情 | `POST /amzStaServer/openapi/inbound-shipment/shipmentDetailList` |

令牌获取/续约使用现有服务端鉴权配置。领星应用密钥、令牌和签名不会进入浏览器；若领星应用启用出口 IP 白名单，需登记实际服务端访问领星时使用的公网出口 IP。

## 单据接口

- `POST /api/v1/documents/:id/lingxing-preview`：`operationId`、`expectedVersion`。只查询当前已保存版本的商品；返回资料候选、缺项和权限诊断，归档来源。
- `POST /api/v1/documents/:id/lingxing-apply`：`operationId`、`expectedVersion`、`previewOperationId`、`reason`。从服务端重读归档预览并建立 v2 修订及只读来源快照。`confirmPrices` 参数为旧客户端保留，默认 `false`，不影响 v2 自动计算价格。

两步均验证管理员、同源、操作编号和单据版本。已有正式文件、取消或被替代的单据不能直接补写。预览后若单据版本改变，应重新查询。重放同一操作编号不会重复采用；不同操作编号可重新取得来源。

默认自动任务入口为 `POST /api/v1/documents/automations`，状态读取、统一 requirements/supplement 和合并下载接口见[单据 API](../api/documents.md)。自动处理复用上述预览和采用的归档及版本边界；技术失败保留已完成的准备检查点，任何范围未通过时整批不发布文件。公共字段只填一次，商品、箱和地址字段由服务端描述符限定目标，保存使用整批与单据版本原子核对。真实缺项、权限不足及匹配歧义显示待补，不伪造值。混装票沿用既有代表商品和数量规则，显示提醒但允许随整批输出供后续修改；仍须人工复核生成文件。

单次最多查询 50 个不同完整商品身份、200 次业务尝试；Listing 按店铺每批最多 10 个 MSKU，精确搜索并完整分页。分页未完成或结果有歧义时不采用匹配。单张图片不超过 2 MiB，预览图片合计不超过 8 MiB。某接口权限被拒绝后，本轮停止重复请求该接口，其余成功来源继续保留。

## 字段边界

- 商品以完整 sid/MSKU/FNSKU/SKU 匹配，并核验本地产品 ID/SKU，避免跨店铺或错配产品。
- v1 历史规则优先采用与目的国家对应的清关价格/币种。报关价、默认清关价和国家价格保留来源区别；取数成功不等于本票价格已确认。v2 使用上文归档的 Listing 普通售价，不采用该人工确认规则。
- 图片在预览时下载为受控 PNG/JPEG 快照；限制协议、目标地址、大小、超时，不在生成文件时请求远程图片。下载失败保留缺项。
- 领星未返回可用图片时，可在本票商品申报中上传 PNG/JPEG 或显式读取公开 HTTPS 图片直链；保存修订后采用图片快照。仍无图片时显示提醒并允许生成待复核文件，图片列留空；价格、币种、地址和数量等其他校验继续执行。
- 按当前业务规则，带电、带磁、液体、粉末、危险品在单票中均默认“否”，保留已有明确填写的值（包括“是”）并允许修改。这是本系统的业务默认值，不表示领星已核验其属性。
- 当前收件地址以绑定 FBA 的领星货件快照为准，不再匹配本地地址簿。自动采用要求全部成员具有完整、无冲突且国家匹配的地址；缺项或冲突须人工核对。2026-10-29 起，列表街道兼容 `address_line1/2/3`，同时保留详情的 `addressLine1/2/3` 及旧 `address_line_1/2/3`。
- B3 常规采用领星列表 `destination_fulfillment_center_id` / 详情 `warehouseId` 的一致物流中心编码；候选中单独归档原始 FC，不以需求输入 FC 代替来源证据。货代特殊编码或同仓多地址须按指定 SHA-256 版本的参考库，以国家、FC、完整领星地址唯一匹配；无唯一匹配、含公式或资料有问题时需人工填写编码、原因并确认。代码匹配不替换领星街道。保存记录采用来源和参考行，新导出须核对已采用版本；原件缺失或哈希改变不回退 FC。
- 直接打开旧单据详情保持原行为：旧空白地址只在本地显示待保存修改，不自动建立修订，也不代勾确认。默认制作入口与列表草稿编辑可显式启动自动任务；打开旧链接或查看已有文件不隐式启动后台写入。
- 已有人工地址、人工模式、已确认或已引用地址以及本次用户修改不因异步目录刷新被覆盖。查询失败保留当前内容，可重试；目录更新不静默替换已采用版本。采用领星商品资料仍不会覆盖用户地址。
- 货件地址仅在各来源非空字段一致时补充，空字段可由详情补齐；两个不同的非空地址仍需核对。
- 不从商品资料自动推断 VAT、交税方式、报关方式、预约配送时段或卖方主体。可直接补齐本票最终资料，无需强制建立主体、渠道和税务档案；选择了渠道档案时，丰信服务仍须与其明确维护的服务匹配。
- 丰信模板使用整票币种，按货件目的国家自动确定：美国 USD、英国 GBP、德国/法国/西班牙/意大利 EUR。已支持国家只读，旧草稿错值在保存新修订时归一化；未知国家保留人工币种。原有按店铺、渠道、目的仓及国家等分票规则继续生效；跨币种混票出单以 `DOCUMENT_TICKET_CURRENCY_CONFLICT` 阻塞，须拆票。v1 商品币种为空时采用本票有效币种，显式不同币种仍须解决冲突；人工确认绑定有效单价和币种，组合变化须重新确认。
- 客户订单号、表头参考号、贸易条款不再提供输入，新修订和当前导出统一留空；逐箱 `PO / Reference ID` 保留。备注、预约配送时段及商品申报单位可空，单价、有效币种和其他实际出单必需资料仍须齐备。
- 权限拒绝、查询失败、查无商品、返回字段空白分别显示；接口文档存在字段不证明当前账号已开通或已维护。

## 验证

本地验证覆盖固定查询白名单、身份匹配、国家价格选择、默认未确认价格、地址补齐/冲突、权限错误、预览绑定、采用保留已有资料及图片下载边界。当前账号的实际授权结果需以具体查询返回为准。

`corepack pnpm test`、`corepack pnpm build`、前端浏览器回归已通过。`node scripts/m4/verify.mjs` 在独立 PostgreSQL 中额外验证采用归档候选、版本和来源保存、重放幂等、错误操作人/过期预览/归档损坏完整回滚，以及原有生成和恢复流程；不在业务数据库中制造验收记录。
