# 外部接口能力

版本：1.4。更新日期：2026-10-23（`Asia/Shanghai`）。

本文记录外部系统的能力边界。公开文档字段不等于企业账号已经授权或每票数据一定完整。截至本次更新，探测脚本已用真实账号取得店铺列表和 STA 货件列表、详情、装箱数据；这仅证明已测账号、接口和样本的可用性，不代表生产 M2/M3、其他店铺国家或未测接口通过验收。原始运行及参考记录抽样依据见[领星真实样本验证记录（私有研究说明）](../research/README.md)。

## 领星只读能力

| 目标 | 接口 | 用途 | 状态 |
| --- | --- | --- | --- |
| 店铺映射 | `GET /erp/sc/data/seller/lists` | 获取 sid、国家、站点和授权状态 | 账号目录与授权须在具体环境确认，真实目录不公开 |
| 货件商品 | `POST /amzStaServer/openapi/inbound-shipment/shipmentDetailList` | 通过 sid + shipmentConfirmationId 获取 MSKU、FNSKU、品名、SKU、申报量 | 非 STA、缺字段和不同账号范围须独立验证 |
| 装箱明细 | `POST /amzStaServer/openapi/inbound-shipment/listShipmentBoxes` | 获取箱、箱内商品、quantityInBox、尺寸和重量 | 同批 STA 样本已取得真实多箱、混装和多配方；跨次箱身份稳定性待验证 |
| 通用货件 | `POST /erp/sc/data/fba_report/shipmentList` | 获取 is_sta、sta_inbound_plan_id、quantity_shipped、quantity_shipped_local、quantity_received | 同批 STA 样本成功；已有申报/装箱一致及少收、多收案例，业务口径和处理仍需确认 |
| 业务渠道（运输方式） | `POST /erp/sc/routing/storage/shipment/getInboundShipmentList` | 按已找到的 sid/FBA 查询关联发货单，以 `method_name` 提供头程运输方式 | 已接入在线表“通过 FBA 补全信息”；本次口径调整未新增真实账号调用验证，文件导入不自动请求此接口 |
| 本地库存 | `POST /erp/sc/routing/data/local_inventory/inventoryDetails` | 获取成品仓 SKU 的 product_valid_num | 本次未测试，后续库存模块 |
| FBA 商品档案 | `POST /erp/sc/routing/fba/shipment/getFbaProductList` | 按本票身份核验商品，取得本地产品 ID、图片和销售链接 | 单据资料预览接入；账号权限及维护完整性以实际查询为准 |
| 本地产品申报/清关资料 | `POST /erp/sc/routing/data/local_inventory/productInfo` | 读取中英文申报品名、HS、材质、用途、品牌、型号、单位、国家价格和币种、特殊属性 | 单据预览后显式采用，默认不确认价格 |
| 主体候选 | `POST /basicOpen/stockSubject/list` | 查询主体名称、类型和状态 | 仅作候选，不提供完整主体地址/VAT，不自动采用为卖方主体 |

真实样本和目录统计仅在受控本地保存。缓存复用不能重复计为新样本，已测查询也不能证明库存、标签、打印或其他接口具有权限。

## 真实样本对算法的约束

- `sid + sta_inbound_plan_id` 只提出候选组，须人工确认业务子批次；相同商品、配方、日期或目的仓不授权自动合并，不固定每组货件数或每票箱数。
- 商品核对在店铺和货件作用域内保留 MSKU、FNSKU、SKU；正式算法以完整身份组合核对并识别缺失/冲突。配方按完整身份和箱内数量规范化，忽略商品顺序；货件比较箱配方多重集，忽略箱顺序但保留相同配方的实际箱数。不同 FBA 的相同配方不是重复数据。
- 总件数相同不足以判断配方相同。虚构例子：两个箱各 12 件，第一个为商品 A 的 8 件和 B 的 4 件，第二个为 A 的 5 件和 B 的 7 件，属于不同配方。箱编码按实际箱记录生成。
- `quantity`、`quantity_shipped`、`init_quantity_shipped`、`quantity_shipped_local`、`quantity_received` 和装箱合计分开保存。真实样本有接收量少一件、多一件；收货差异不能反向修改原申报或装箱，数量口径及放行规则须业务确认。
- 完整重复行保留并提供差异诊断。虚构例子为来源 30 件、申报 24 件、重复记录 6 件；诊断去重不授权修改原件或自动确认。
- 箱名兼容 `boxName` 和 `box_name` 并保留原始键。早期报告只查 `box_name` 的空值属读取误报。`localBoxId` 是货件内序号，可跨 FBA 重复；`P1 - Bx` 箱名属于另一编号域，可不连续，不能代替内部箱 ID。
- 保存内部箱 ID 和关联 sid/FBA，并保留 `boxId`、`packageId`、`localBoxId`、箱名候选；一次响应不能证明跨次刷新或装箱变更后标识稳定。
- 箱重和尺寸保留原值、LB/IN 等原单位；输出 kg/cm 时显式换算并保存展示精度。本批发货日期、承运编码存在空值，不能用送达窗口代替业务发货日期，或用 `Other`、平台SPD/LTL推导业务渠道。业务渠道指头程运输方式，在线补全读取另行查询的关联发货单 `method_name`，不以物流渠道名称 `logistics_channel_name` 回退。

上述是数据模型、算法和验收约束；业务子批次与 STA 计划的关系、数量差异处理和箱身份变更策略仍需业务确认。验收条目见[验收场景](../acceptance/scenarios.md)。

## 文件生成字段边界

领星接口可以为文件生成提供货件和平台数据：

- `seller/lists` 提供 sid、店铺名、国家、区域、Marketplace 和授权状态。
- `shipmentList` 提供 FBA 号、Reference ID、目的 FC、状态、STA 标记、STA 计划 ID 候选分组依据、承运方式候选、地址、日期和多种数量口径；本批部分日期、承运字段为空。
- `getInboundShipmentList` 提供关联发货单的运输方式 `method_name`，在线补全以有效单的唯一运输方式优先填入或覆盖手填渠道，无需 HYKD 等旧缩写。查询按找到的 sid/FBA 精准限定并完整分页，只接纳 `status=-1/0/1/2`；多个运输方式、运输方式缺失或查询失败保留人工确认，不以 `logistics_channel_name` 或平台 SPD/LTL 回退。新规则不回写历史导入、需求或确认快照，渠道必填规则不变，详见[运输方式核验与实现边界](./fba-logistics-channel.md)。
- `shipmentDetailList` 提供 ASIN、MSKU、FNSKU、SKU、平台品名、标题、图片 URL、申报量、地址和送达窗口。
- `listShipmentBoxes` 提供箱号候选、箱名（`boxName/box_name`）、箱内商品、单箱数量、箱重、尺寸和单位；真实样本已取得这些箱标识，但接口示例中的 `boxId/packageId` 可能为空，仍须处理缺失。
- `getFbaProductList` 提供平台商品图片、ASIN 链接、平台品名、标题和商品身份。
- `inventoryDetails` 提供本地仓可用量等库存快照，但库存不是发票生成的必需字段。

以下内容不应从这些货件接口直接推导：9710/9810/买单/退税报关方式、包税/不包税/自税递延、VAT、最终申报品名、材质、用途、品牌、型号、HS、申报单价、币种精度、卖方主体和模板格式。它们应由项目数据库中的商品申报档案、主体档案、地址/渠道/税务/价格规则和模板版本提供，并保留生效版本。业务渠道按关联发货单的原始运输方式 `method_name` 保存，不由 Amazon 承运字段或运输类型推导旧业务缩写。

“货件接口不提供”不表示领星的产品接口不提供。单据资料查询现通过 `getFbaProductList` 关联 `productInfo`，将已维护的申报/清关资料作为有来源的候选写入本系统资料版本。主体、税务与本票决策仍按各自来源核验。具体权限、采用流程和字段边界见[领星单据资料查询与权限](./lingxing-document-profiles.md)。

字段与数据库落点的完整矩阵见[发票文件生成接口与数据库矩阵](../business/invoice-file-generation-api-db-matrix.md)。

## 首版只读边界

首版只调用查询接口，不创建领星发货单、不分配库存、不修改物流信息。外部写入属于后续模块，必须单独通过真实账号和回查验收。

## 鉴权与运行要求

- AppId/AppSecret、access_token、refresh_token、IP 白名单和签名配置由服务端保存，不能进入前端或日志。
- 业务请求需要 access_token、app_key、timestamp 和 sign；签名有效期和 refresh_token 一次性使用规则按官方文档实现。
- 业务接口令牌桶容量为 1，按 appId + URL 管理；Worker 必须串行控制、分页拉取、处理超时和限流，不把容量解释为固定 QPS。
- 原始请求摘要、响应快照、分页游标、错误码和重试次数写入任务记录；不保存密钥。
- 运行报告分别记录新查询、成功快照复用和离线重算；缓存不能证明跨次行为。请求预算、串行间隔和限流恢复按具体运行记录验证，不从少量成功抽样推断固定 QPS、配额或续约能力。
- 后续验证优先复用已有快照，按验证目的选择少量新 FBA，预先限制请求预算；出现限流停止本轮并保留证据，不能无边界重试或遍历整本参考记录。
- 两种脚本策略须区分：普通 `probe.mjs` 遇 HTTP 429 或业务码 3001008 最多额外重试两次，间隔为 1、2 秒；定向参考抽样包装器采用更严格的总预算，遇限流立即停止、不重试。前者不代表已验证真实限流恢复，后者的停止策略也不等于普通脚本默认行为；生产 Worker 的长期调度仍需单独实现和验收。
- 连接超时、HTTP 状态、业务错误码和查无货件分开分类。早期 HTTP 200/业务码 403 表示授权校验拒绝，不是无货件或缺字段；只有成功响应且范围完整后才能判断未找到。

## API 样本确认清单

| 项目 | 本批状态 | 后续真实验证 |
| --- | --- | --- |
| STA 单商品、多商品、多箱、混装、商品跨箱 | 公开版本不提供真实样本清单 | 按代表性国家、渠道及验收要求补足真实流程 |
| 同计划不同箱数、单票多配方、独立业务组 | 公开示例仅说明约束 | 实际组与计划关系、跨计划分组和人工确认须单独验证 |
| 非 STA 历史货件 | 未完成 | 详情/装箱兼容性及降级路径 |
| 箱标识和顺序 | 已见 boxId/packageId/localBoxId、boxName，商品及箱顺序可不一致 | 跨次查询、修改装箱后的稳定性及内部 ID 迁移 |
| 数量 | 已有申报/装箱一致、收货少 1/多 1 的真实证据 | 初始/当前申报变化、未发货量为 0、业务口径和差异确认 |
| 缺字段、空装箱 | 已见日期/承运编码空值；箱名旧误报已定位 | 缺品名、SKU、FNSKU、箱号及空装箱的真实返回和异常处理 |
| 运行异常 | 已有连接超时、业务 403；本轮串行抽样未限流 | 真实多页完整性、限流恢复、token 刷新、重复新请求及长期运行 |
| 标签、打印、库存、旧版降级 | 本次未测试 | 按后续模块单独确认接口与权限 |

本地模拟测试或离线回放可验证解析和错误处理，但不能证明真实分页、token 续约、授权范围或生产端到端行为。探测报告的“核心字段通过”也不等于业务数量口径、实物装箱或生产验收通过。

## 降级原则

接口异常、关键字段缺失、分页不完整或准备量与确认对照量不一致时，保存快照并将受影响子批次标记为异常，禁止正式导出；收货少收/多收单列，不反向修改准备量。正式主数量和接口数量冲突处理仍待确认。同周其他已确认正常子批次可以继续；允许Excel或补录回退，须标记来源并重新确认版本。

文件生成还必须阻止以下情况：缺少正式模板、商品申报档案、主体、税务/币种规则、内部箱 ID 或有效人工确认版本。此时只允许生成草稿或差异报告。
