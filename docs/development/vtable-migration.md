# 发货工作台与发票单据 VTable 改造

日期：2026-10-31。

## 已实现范围

两模块默认使用 `@visactor/vtable@1.26.8`。发货货件／商品／逐箱视图，以及工作台内来源、历史、导出和待核对操作表格，均采用新网格。发票侧覆盖单据记录、可选货件、逐箱资料、来源、申报数量、最近任务、文件、修订及复核历史九类表格。

顶部筛选、搜索、分页、导出和业务操作沿用原语义。发货次历史、自动出单任务通过独立按钮打开浮窗；批次范围、批量选择与安排操作集中在表格工具栏。商品、售价、图片、地址表单和独立设置页面没有被改成电子表格；本次没有新增公式、拖填或全库列头筛选。

## 发货三视图交互优化

发货工作台三视图采用以下交互；单据侧的后续统一见下一节。其他工作区继续沿用原交互。

- 货件分组使用“展开三角、序号、选择、货件”等显式列；商品子行不显示展开按钮。货件、批次、目的仓、店铺、国家、渠道分别成列，其他组合字段保持原样。
- 货件分组标题栏在列设置之前提供“全部收起／全部展开”，一次更新当前页全部货件的商品明细状态，保留逐票三角控制、货件勾选和列偏好；商品平铺、逐箱长表不显示这两个按钮。
- “列展示设置”提供搜索、显隐、全部显示和恢复默认列。功能列及 FBA 固定显示；新出现的动态箱列默认显示，隐藏列保留已调整宽度。
- 列显隐、宽度和每页 20／50／100 票按账号、视图保存在当前浏览器，配置带版本和校验，存储不可用时保留当前页面设置；不保存业务记录或筛选内容。
- 行内三个点与底部“查看 / 操作”共用菜单，包含当前记录摘要、完整详情和现有业务操作；生命周期弹窗持有者独立于菜单，关闭菜单不会丢失提交或原请求。
- 行导航、定位、详情入口及分页置于表格底部；页容量改变时回第一页，继续按完整货件分页并保留跨页选择。筛选区域默认收起，已应用计数及未应用修改提示常驻；展示方式和业务按钮保持可见。
- 按后续布局调整，过滤条件入口及计数位于顶部操作栏右侧；范围切换与批次选择器位于批量操作按钮之后，展示方式位于批量栏右侧、导出勾选框之前。列设置入口位于表格标题栏右侧；窄屏按组换行，批次浮层按触发按钮位置自动选择方向并限制在可用高度内。
- 可按住鼠标中键横向拖动 Canvas；只改变横向位置，松键、取消、失焦、失活和卸载均释放捕获。保留原滚轮、触控板及滚动条。
- 共享组件以稳定列 key 映射定位、编辑和选择，旧布局继续使用原生序号列；结构调整保留当前行及视口，冻结列按容器实际宽度重新计算。

## 发票与单据交互统一

- 单据记录显式区分名称、编号、订单号、发货次、状态、FBA／来源组数量、FBA、店铺、版本和更新时间。过滤条件默认收起，保留应用计数和未提交修改提示；每页 20／50／100 张仍调用现有 SQL 分页接口，改变容量回第一页。
- 可选货件将 FBA、批次、目的仓、店铺、国家和渠道分别成列，保留按发货次读取、搜索、多选及整批准备情况。来源表同样拆列；历史快照只有批次 ID 的地方直接展示 ID，不从当前批次推断历史名称。
- 逐箱资料按 demandId 分组（不按 FBA 文本合并），采用展开三角、序号、选择、FBA、箱身份、五个编辑字段和三个点。标题栏提供全部收起／展开及列设置；过滤之外和收起组中的选中箱分别计数。
- 收起分组、隐藏列等操作先完成单元格编辑；校验定位先完成当前输入，再清除本地筛选、展开目标组、恢复目标列，按稳定箱和字段定位。桌面详情与自动来源按需打开，≤768px 继续提供完整单箱五字段与前后箱编辑。
- 单据记录、候选、逐箱、来源、申报数量、自动任务、文件和两类历史均采用标题栏列设置、底部导航及中键横移。菜单显示摘要、现有动作及完整详情；文件下载、任务删除仍使用原业务回调和独立弹窗持有者。完整返回的辅助资料不增加分页。
- 单据列显隐、列宽及主表容量按账号和表格标识保存在本浏览器。带版本和校验的共享存储通过订阅同步同表多个使用者，避免容量与列设置互相覆盖；不保存业务数据、筛选值或选择记录。恢复默认列只重置列显隐和宽度。
- 四步向导、批量人工覆盖确认、恢复自动值的 null、统一保存、修改原因、版本／幂等协议、409 恢复及离开保护沿用原流程。商品、图片、地址和售价表单保持原结构。

## 实现与数据边界

- `ScmDataGrid` 包装 VTable 核心，绘图库按需加载。普通行 32px，多行摘要 56px；Canvas 主题从项目 CSS 变量读取字体、白底、暖灰表头和边框，配合浅绿选中态及圆角操作按钮。业务冻结列数量正确计入序号列，小屏冻结区上限为可用宽度的 70%。
- 数据、选择和操作以稳定业务 ID 为准。网格使用独立展示记录，避免 VTable 编辑直接修改查询缓存。数据、可编辑状态、禁用状态和错误样式变化通过行更新同步。
- 每个可编辑网格只持有一个原生输入覆盖层。支持点击、Enter／F2、Tab、Esc 和中文组合输入；保存、筛选和切换前完成编辑。等待中的组合输入可在取消或卸载时安全结束。
- 逐箱草稿继续统一保存，保留覆盖人工值确认、跨筛选选择计数、恢复自动值和冲突恢复。正在编辑的箱暂留在筛选结果，离开后重新计算。窄屏提供当前箱完整五字段及上一箱／下一箱编辑区。
- Canvas 操作显式检查业务禁用条件和祖先 `fieldset disabled`／`inert`，避免绕过原表单锁定。错误定位先调整本地筛选，再按箱 ID 定位、滚动并聚焦字段。
- `GridTableScope` 只在目标工作区生效；共享 `BatchTable` 在其他模块继续使用原实现。辅助表保留当前记录的真实 React 控件和可访问详情，不生成隐藏全量 HTML 表格。纯结构单元格通过显式 `gridCells` 协议展开，避免商品、箱列错位。
- 发货汇总行采用浅绿底、加粗身份，子行缩进并标注“商品 N / 总数”；只有汇总行显示展开三角。行内三个点和底部入口打开记录菜单，完整详情承接地址、来源和状态，不再在网格下方常驻大块重复详情。单据逐箱桌面编辑使用单元格输入，手机保留原生当前箱编辑区。
- 发货批次选择器保留状态、搜索、分页、新建、生命周期操作，并保护嵌套弹窗的 Esc、Select 浮层和提交锁定。待核对操作恢复器常驻工作台，关闭发货次浮窗后继续轮询。
- 保留 HTTP API、DTO、版本号、幂等操作号和数据库结构。后端采用请求内索引、页内明细物化和同事务依赖读取去重；详见[后端报告](./vtable-backend-performance.md)。

## 前端压力诊断基线（2026-10-30）

本机 Chrome、1440×1000，单轮诊断值；计时从切换数据集至网格可交互，包含展示记录生成及 React 更新，不包含生产网络。帧间隔来自实际横纵滚动期间的 `requestAnimationFrame` 采样，不是纯绘制函数耗时。

| 已加载行×列 | 首屏 | 跳至末行 | 滚动帧间隔 P95 | 页面元素 | 页面 Canvas | JS 堆快照 |
|---|---:|---:|---:|---:|---:|---:|
| 10,000×50 | 620ms | 208ms | 17.4ms | 191 | 6 | 约162MiB |
| 50,000×100 | 3,892ms | 266ms | 17.6ms | 191 | 6 | 约369MiB |

页面同时包含五个小型功能夹具和一个性能网格，因此 Canvas 总数为 6，性能表自身始终只有 1 个。反复挂载／释放后 Canvas 数量受控。320、390、768、1024、1440、1920px 均验证无整页横向溢出；冻结身份列通过水平滚动前后的像素对照验证。

CDP 观察五轮功能网格挂载／卸载：window blur 1→1、resize 5→5，document pointerdown 10→10、scroll 0→0；当前 Canvas 七类拖动钩子均为 1→1，五个已卸载 Canvas 的对应钩子均为 0。该检查证明这些观测点没有累积，不代表对整个浏览器内存泄漏的完整证明。

加载后的即时帧间隔 P95 分别为 33.9ms、85.5ms，表明大数据初始化阶段仍有停顿；完成加载后的实际滚动采样接近 60Hz。该夹具的全量数据生成、GC 和表格初始化均在浏览器中完成，不能将滚动帧率解读为全程无长任务。

原始结果为 `.local/vtable/grid/verification-summary.json`。这些数字受硬件、焦点、JIT 和 GC 影响；没有同口径旧 UI 首屏对照，不能解释为生产 SLA 或内存无增长的证明。五万行完整加载已有明显内存成本，实际页面继续采用服务端分页。
