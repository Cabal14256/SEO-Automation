# 在线渠道粘贴与发货表更新（2026-11-02）

范围：相对 `c81b68e` 的本地变更，为当日服务映射发布后的独立更新；本文不代表本轮 GitHub 推送或 VPS 部署已完成。

## 在线导入渠道

- 业务渠道保留下拉选择，可在渠道框收起或展开时粘贴单格、多行渠道列；从 FBA 等列粘贴完整表格时，也识别其中的渠道列并保留其他列的位置。
- 新增 `pinyin-pro@3.29.5`，按当前已启用运输方式的实际名称生成完整拼音首字母。忽略首尾空格及缩写大小写，完整名称和目录字面值优先；只有唯一匹配才采用实际名称，不使用固定简称表，也不做局部缩写猜测。
- 同缩写有多个候选时保留输入并显示候选，未知或停用值保留并提示人工选择；新提交前继续检查渠道有效性。空白仍允许按 FBA 自动补全。
- 表格可先于运输目录加载完成，目录就绪后归一当前可编辑草稿中的缩写；接收结果不确定的提交保持锁定，仍用原操作号和原始载荷重试。历史数据库快照及文件导入原值不回写。

共享 `SelectField` 增加粘贴事件支持，使弹出的列表也能接收渠道粘贴；本轮没有增加通用下拉框拼音搜索。粘贴继续遵守行数、列数及单元格长度上限，错误时保留现有表格。

## 发货表 v9

新生成发货 XLSX 的汇总及区域商品表至少保留“箱1～箱10”，超过十箱按实际最大货件内箱序继续扩列；模板版本为 `shipment-record-v9`。页面预览仍至少显示五列，箱序从每个 FBA 的箱1开始，逐箱明细保留真实箱码。商品数量、顺序及票间空行规则保持，历史文件不改写。

## 部署与验证入口

本轮**没有新增数据库迁移**。部署须按锁文件安装新增前端依赖并重新构建，API 与 Worker 使用同一更新版本以生成 v9 文件。

本轮 `pnpm typecheck`、`pnpm lint`、`pnpm build`、`pnpm privacy:check`、`pnpm privacy:history` 均通过；`workbook` 11 项、`report-order` 5 项及 `online-import-pipeline` 14 项测试通过。`scripts/t33/online-channel-paste-browser.mjs` 14 项全通过，覆盖缩写、歧义、停用值、真实剪贴板、多列表格、目录延迟和窄屏交互，真实业务写入及外部请求均为 0。本地 Linux 路径映射运行时的 v9 十箱列回归也已通过；该检查不等同于 VPS 部署验收。实际发布状态以发布收据为准。业务边界见[运输方式说明](../integrations/fba-logistics-channel.md)和[发货表 API](../api/batches.md)。
