# VTable 改造：后端读路径验证

日期：2026-10-30。环境：Windows、Node.js 24.22.1；本地合成数据，不连接真实账号或生产数据库。

## 实际改动

- 发货投影为确认、成员、快照、修订和产品箱分布建立请求内索引，复用同一修订的校验结果。先构建筛选与计数摘要，仅对选中页物化重量、尺寸等完整箱分布。
- 来源在选页后按当前页需求读取，并在 SQL 中只提取填写日期字段；采用版本、来源顺序和包装天数规则保持一致。
- 单据列表使用同事务 `DocumentReadContext`，共享确认组、候选范围、资料与模板版本和归档文件校验。缓存按稳定身份、版本和哈希区分，失败也仅在当前请求复用；权威写入不共享此缓存。
- 指定发货次/月的候选读取不再扫描全部周批次，单票列表校验只展开目标完整货件。自动任务列表仅选择序列化实际需要的列，仍保留完整响应契约。
- 公共 HTTP API、DTO 和数据库结构均未改变。

## 新旧投影对照

将改造前 HEAD 中的投影函数与新函数放在同一 Node 进程运行，使用相同输入、固定生成时间、每页 20 个完整货件。每货件 10 个商品；箱按商品分配，具有冻结确认、编码、月份及组统计。比较全部响应字段，而非只比较当前行数。

| 输入需求 | 商品行 | 箱列 | 改造前 | 改造后 | 加速比 | 响应字节 | 输出商品行 | 全响应一致 |
|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 1,000 | 10,000 | 50 | 655.3 ms | 334.3 ms | 1.96× | 543,189 | 200 | 是 |
| 5,000 | 50,000 | 100 | 6,254.1 ms | 2,432.0 ms | 2.57× | 840,310 | 200 | 是 |

上述数字为本机单轮诊断值，包含 JIT/GC 等影响，不作为部署环境 SLA。数据与运行产物保存在 `.local/vtable/backend/workspace-performance.json`，临时对照程序为 `.local/vtable/backend/benchmark.ts`。

## 永久复现入口

运行版本库中的 `scripts/vtable/workspace-benchmark.mjs`。默认对当前投影执行上述两档夹具，各测三轮，并校验总数与页内完整货件数量：

```powershell
corepack pnpm --filter @scm/server exec tsx ../../scripts/vtable/workspace-benchmark.mjs
```

与本次改造前的投影逐字段对照，每轮响应不一致会直接失败：

```powershell
corepack pnpm --filter @scm/server exec tsx ../../scripts/vtable/workspace-benchmark.mjs --baseline 4a93ef850882ec699bba554dd18dda4e62ed714e
```

可使用 `--iterations 1` 作快速诊断，或用 `--output .local/vtable/backend/custom-report.json` 指定报告文件。默认报告为 `.local/vtable/backend/workspace-performance-current.json`，包括逐轮时间、中位数、响应字节和基准提交。

`--baseline` 通过无 shell 的 Git 调用读取指定提交，只将历史投影生成到 `.local/vtable/backend`，不会覆盖源码。历史投影使用当前域辅助函数；这是投影算法对照，而非启动整个历史系统。无效 Git 引用、无法加载历史函数或任何响应差异均以非零状态退出，不会静默跳过比较。

## 回归结果

- 服务端完整测试：92 个文件通过、3 个文件按现有条件跳过；1,410 项通过、57 项跳过。
- 变更服务端文件 ESLint 通过，服务端 TypeScript 检查通过。
- 新增验证：非当前页不读取箱尺寸但最大箱列覆盖全命中集；页后来源补全与原有完整投影一致；同请求共享确认组；并发读取去重；不同归档哈希隔离；跨请求重新校验；指定发货次不读取无关周批次。
- 保留冻结快照、组确认失效、月份合计、完整货件分页、来源版本及单据派生失效状态分页等既有断言。

## 性能边界

此轮减少重复查找、对象展开、数据库查询和文件 I/O，但全局摘要及统计仍需读取相应数据；没有新增数据库物化读模型。单据/自动任务 DTO 仍包含原有完整数据，因此不能据此宣称网络响应体已经概要化。

未对真实数据库运行接口压测，SQL 实际耗时与生产文件 I/O 延迟没有在本报告中编造。请求内确认组/文件读取上限以自动测试验证；部署环境仍应以脱敏真实结构样本测量接口时间、查询计划和响应体量。
