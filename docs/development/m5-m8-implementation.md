# M5–M8 实施与技术验收

本文记录 2026-10-22 的 M5–M8 阶段交付与验收边界；后续变更和完整迁移范围见[当前实现状态](./implementation-status.md)及[运行维护](../operations/runbook.md)。业务时区为 Asia/Shanghai。阶段需求见 [实施计划](../archive/plans/m5-m8-plan.md)。

## 已实现链路

- M5 从已复核且依赖有效的 M4 文件建立准备组，逐箱核对商品、组合关系、出库仓及辅料。人员在领星操作后登记实际单号、分配、缺货或取消及凭据，范围或数量差异保持待处理。
- M6 引用 M4 文件和哈希，登记提交、接单或拒绝反馈，回收订单、跟踪号、PDF 箱唛、毛重及计费重。放行检查包括 M5、接单、标签、重量及独立线下复核。部分交接绑定内部箱 ID；实际已经交出但条件不全时，填写异常原因和凭据保留事实。领星发货独立核对。
- M7 采用美欧样本七页布局：报关单、申报要素、填制规范、发票、箱单、合同及委托书。保留固定标签、合并、行列尺寸和打印版式，清除历史值。正式文件核验 M4/M6、商品身份、数量、单位、重量及币种。报关与 9810 分别登记编号、状态、提交文件和反馈。
- M8 保留原账单，提供标准 XLSX 预检和人工录入，按实际外部单号人工分摊。同币种金额严格守恒，预估不替代实际；补账和负数退款新增行。人员回填后登记前后值、拟回填金额及凭据。
- 批次归档覆盖完整有效箱范围，实时复核 M5–M7 及费用，生成 ZIP、JSON 关联清单、SHA-256 和 XLSX 文件索引。补账、来源及关联资料变化使旧归档失效，历史字节保留。

## 入口、默认与限制

发货管理新增“领星单据与分配”“物流与交接”“报关与 9810”“批次归档”；费用入口为 `/finance`。旧 M2–M4 路由与向导保留。接口见 [工作流 API](../api/workflows.md)。

- **领星始终只读**。创建单据、库存分配、确认发货、备注及费用修改都由人员在外部系统执行，系统保存核对结果和凭据。
- M5、物流、报关及费用分别分组，按箱关联。一张 M4 文件可对应多张外部单，费用细化到外部单号。
- 净重、数量单位换算、辅料及“整箱／整单”关联须明确确认，不从历史值自动推断。商品和运费分别保存币种，不自动换汇。
- 跨国报关默认拆组，例外逐组确认依据。当前样本打印区支持最多 16 种完整申报商品；多个箱子同商品聚合。超出容量明确阻止生成并要求分组，不截断。
- 运行模板为 XLSX，原 XLS 仅作受控参考。9810 提供填写核对清单；没有平台专用导入协议，不声称可直接批量提交。
- 单附件不超过 10 MiB，PDF／图片验证文件签名；归档关联文件总量上限 256 MiB。下载校验授权及实际文件哈希。

## 验证与升级

```powershell
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
corepack pnpm build
corepack pnpm privacy:check
corepack pnpm m5-m8:verify
corepack pnpm m5-m8:browser
```

隔离集成使用独立 PostgreSQL、DATA_DIR 和合成身份，禁止外部业务请求。覆盖 M2/M3/M4 真实技术链路、M5–M8、重放、冲突、缺货、部分交接、七页复核、分摊、补账、归档失效及独立恢复。浏览器使用 HTTP 夹具，覆盖操作恢复、下载、键盘和桌面／窄屏。技术通过不替代接收系统实际导入、真实批次及业务签收。

本轮结果见 [技术验收记录](../acceptance/m5-m8-technical.md) 和 [前端操作与验证](../acceptance/m5-m8-frontend.md)。

升级前按 [运行说明](../operations/runbook.md) 备份数据库和 DATA_DIR，停止旧 API/Worker，执行 `corepack pnpm db:migrate` 应用 `0017_flashy_surge`，启动新版本。迁移仅新增工作流表，不补造旧批次完成事实。独立 Worker 处理 `workflow-file-export`；恢复后核对来源文件和未决生成任务。
