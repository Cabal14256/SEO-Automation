# VTable 浏览器回归入口

运行 `corepack pnpm m4:browser`，按顺序执行表格交互、来源选择、逐箱资料、发票 V2、单票资料、默认值、自动出单、售价兼容和删除九套专项夹具。每套都会启动并释放自己的本地 Vite 与 Chrome，不连接真实业务服务。

`scripts/m4/browser.mjs` 已由旧的单体场景改为上述专项套件的串行入口。旧入口包含已经退休的按周选来源、实物确认和价格确认界面断言；现有专项覆盖当前按发货次选来源、固定申报价格、自动任务与资料修订流程。表格检查通过真实的定位行、Canvas 单元格和当前记录详情执行，不创建隐藏全量 HTML 表格。

每个子进程的退出码、新生成的 `result.json` 及其检查结果共同决定总结果；任何一套失败、证据缺失或中断，聚合入口均返回非零。总报告位于 `.local/m4/frontend/result.json`，包含各套件的耗时、检查数和证据路径。自动出单的实际证据目录为 `.local/m4/document-batch-preflight`。

表格交互专项使用 125 张技术单据验证 20／50／100 分页、折叠过滤草稿、列显隐与宽度持久化、账号及实际逐箱表偏好隔离、菜单稳定记录、删除和 409／提交中 Esc、底部导航和中键横移。响应式截图覆盖 320、390、768、1024、1440、1920px。

逐箱主要业务场景在窄屏单箱 DOM 编辑区验证；另有桌面 Canvas 实际编辑、保存最后字符、Esc 取消后重新编辑的集成场景。分组及隐藏列定位使用稳定字段键定位；共享网格专项补充在 IME 等待中撤销旧定位后不抢焦点，并确认后续定位仍正常。大型网格渲染和通用编辑器交互另由共享网格专项测试负责。
