本文回答一个范围明确的问题：领星 API 和项目数据库规划，能够为发票、清关单或物流 B2B 导入文件提供哪些数据，哪些数据仍需业务主数据或人工确认。

## 结论

文件生成在技术上可行。领星 API 可以提供货件、商品平台身份、目的仓、Reference ID、逐箱商品、单箱数量以及领星记录中的箱重尺寸；项目数据库规划可以保存这些 API 快照、规范化实体、规则配置、人工确认和导出版本。

核心货件与箱字段来源于接口规范和私有验证，真实样本清单不公开，也不代表非 STA、全部国家或正式单据已通过验收；箱名别名、数量口径和分组按[算法说明](./us-allocation-algorithm.md)处理。

领星货件接口不能替代申报主数据。中文/英文最终申报品名、材质、用途、品牌、型号、HS 编码、申报单价、币种、数量单位、VAT、报关方式、交税方式、渠道规则、卖方主体和模板版本，需要项目内维护的主数据或人工确认。当前M1/M2已实现需求、批次、不可变商品箱候选、确认和制表导出；M3独立实物复核及M4申报主数据、单据生成仍未交付。实际关系见[数据模型](../data-model.md)，不沿用本页早期“尚无发货业务表”的结论。

最小可用生成路径是：

```text
领星 API / Excel 回退
  → 保存原始快照
  → 规范化货件、商品、箱和数量
  → 关联商品申报档案、地址、渠道和税务规则
  → 校验必填项、数量和金额
  → 人工确认异常或草稿
  → 绑定模板版本生成 XLSX/XLS/PDF
  → 保存导出文件和数据版本
```

## 模板填写规则

以下规则来自 B2B 模板的批注、下拉项和填写说明。它们是文件生成器的校验/计算规则，不是领星货件 API 的返回字段：

| 规则 | 文件生成要求 | 数据库归属 |
| --- | --- | --- |
| 必填项 | 表头带 `*` 的字段必须有值；缺失时阻止正式导出 | 模板字段定义、校验结果 |
| 服务/渠道 | 从发货渠道清单选择，不能自由拼写；业务渠道与领星 `alphaCode/alphaName` 分开保存 | `channel_rule`、模板版本 |
| 地址库编码 | 填写 FBA 目的仓/地址库编码，由编码回填收件地址；API 地址与地址库不一致时保留差异 | `address_profile`、地址来源快照 |
| 客户订单号 | 可使用 FBA 号，或按已确认的“名称+日期”规则生成；不能在系统内无规则猜测 | 单据分组/文件命名规则 |
| 报关方式 | 支持买单报关、报关退税、普通报关、9710、9810；实际选项受国家/渠道规则限制 | `tax_rule` |
| 交税方式 | 支持包税、不包税、自税递延；自税和递延的 VAT 条件必须校验 | `tax_rule`、`party_profile` |
| VAT | 仅在规则要求或自税/递延场景填写；格式按国家配置，例如 GB、FR、DE 前缀 | `party_profile`、`tax_rule` |
| 国家默认币种 | 美国默认 USD，欧洲默认 EUR，英国默认 GBP；例外必须以生效规则覆盖 | `tax_rule`、`declaration_rule` |
| 同箱多商品 | 同一箱可有多个商品，多个商品行重复相同箱号；不能按商品行数推导箱数 | `box`、`box_item` |
| 申报数量 | 模板字段表示单箱产品数量；整票数量需另行汇总，不能把两者混填 | `box_item.quantity`、数量确认版本 |
| 申报单价和总价值 | 单价为单个申报单位价格；总价值按“单价 × 适用数量”计算。模板禁止把产品申报字段写成 Excel 公式，生成器应写入已计算值并保存计算规则 | `product_declaration`、`declaration_rule` |
| 自税最低申报价 | 截图说明为销售链接价格的 30% 下限；正式启用前需确认适用国家、渠道、币种、价格来源和舍入规则 | `declaration_rule` 版本 |
| 箱号 | 用户确认`FBA号 + "000001-" + 该FBA实际箱数`，“件数”按内部箱UUID去重计数；模板中的`U`不自行加入。箱范围显示与平台单箱ID、内部UUID、周内作业编码分开，不合并异箱规/混装事实 | B2B输出字段、箱范围成员关联、模板版本 |
| PO Number | 等于对应FBA的Reference ID；逐票关联领星列表`reference_id`和详情`amazonReferenceId`，保留来源，缺失或冲突待核对 | 货件修订、PO映射及来源 |
| 货箱重量与尺寸 | 用户指定实测毛重业务口径，取数采用领星登记值/标准箱规；另行实测不一致时以领星值为准。输出KG/CM，重量及长宽高均保留两位小数，保留原值、原单位及差异；舍入方式待定。模板C17:F17没有必填星号，不能据此决定M3复核必填条件 | 箱候选、来源与实测记录、确认版本 |
| 预计送仓 | 需要开船日期、渠道、目的 FC 和预计运输天数；API 的送达窗口只能作为参考，不能替代物流时效规则 | `transit_rule`、货件日期快照 |

模板中的下拉项、批注、地址库、渠道表和预计送仓表都应随 `template_version` 或规则版本保存。模板示例中的数量不作为守恒基准，正式生成仍需使用已确认的输入和数量校验。

## 字段缺失与未获取的区别（2026-10-18）

历史取数记录保留在受控归档，公开文档不发布货件数、箱数、重量尺寸或逐票 Reference 值。字段完整性和来源一致性须逐次验证，不能由历史样本推断其他店铺或未来货件必有完整数据。

- 真实字段缺失：查询成功且sid/FBA唯一匹配后，原始返回未包含字段或值为null/空串；先与领星对应货件及箱记录核对。官方[PDA装箱说明](https://www.lingxing.com/help/article/PDApackBox)记载箱规/重量需维护，部分装箱流程允许不填，也存在未维护导致提交报错的场景；因此“源记录未维护完整”是排查方向，不等于已证明某票成功响应缺失。
- Reference获取未完成：官方[插件说明](https://www.lingxing.com/help/article/PlugInUnit)说明插件可获取在后台创建的AGL/SEND货件Reference ID，并有同步前置条件；对这类货件，若领星也未显示Reference，应排查源数据获取状态。该说明不能推断所有Reference都依赖插件，也不能认定本批样本发生过缺失。
- 请求失败或查无：超时、鉴权/权限错误、sid/FBA不匹配、日期范围查无、非STA能力不兼容或分页未完整，属于未取得可用结果，不能当作某个字段为空，更不能据此覆盖已有成功快照。
- 本地尚未接入：当前Reference已随API完整快照归档，但未进入规范化契约、页面及PO输出；本地不显示PO不构成API缺失证据。缺失值的最终业务处置仍待确认，不自动填0或虚构Reference。

## API 到文件的推荐取数顺序

1. 用 `seller/lists` 建立或刷新 `sid`、站点和国家候选。
2. 用 `shipmentList` 取得货件列表、目的 FC、状态、Reference ID、日期、数量口径和 `is_sta`。
3. 对已确认的 `sid + FBA` 调 `shipmentDetailList`，补齐商品身份、品名、ASIN、地址和详情数量。
4. 对支持 STA 的货件调 `listShipmentBoxes`，补齐箱、箱内商品、单箱数量、重量和尺寸。
5. 对需要库存备注的商品调 `inventoryDetails`，保存查询时点和仓库 `wid`。
6. 将 API 原始返回写入不可变 `sync_snapshot`，再写入规范化货件、商品、箱和箱内商品。
7. 关联地址、渠道、税务、商品申报和价格规则，生成差异与缺项清单。
8. 只有数量守恒、必填项和规则校验通过，并且人工确认版本有效时，才能生成正式文件；否则只生成草稿或阻止导出。

| `transit_rule` | 保存预计送仓规则 | 渠道、FC、时效天数、区域、生效期、来源 |
| `document_group` / `invoice` | 保存分票、成员和单据字段 | 分票条件、成员 FBA/箱、主体、金额、币种、审核状态、版本 |
| `template_version` | 固定模板和输出约束 | 模板文件哈希、格式、适用渠道/国家、明细起始行、版本、状态 |

上表是后续主数据和单据实体的规划，不能视为均已实现。当前数据库已具备M1/M2需求、批次、商品箱修订、同步快照、确认、编码和发货表导出基础；后续按对应模块补迁移与契约。Reference ID当前只随完整API快照留存，还需进入规范化修订与PO输出。

## 不应自动猜测的边界

- `alphaCode/alphaName` 不得直接当作 示例渠道A/示例渠道B/示例渠道C 或 示例物流商。
- `quantity`、`quantity_shipped`、`quantity_shipped_local`、`quantity_received` 不得合并成一个“发货数量”。
- 平台 `productName`、`title` 或 ASIN 页面不能直接替代最终申报品名、材质、HS 和用途。
- 领星装箱重量和尺寸不能自动声称为线下实测毛重。
- 缺失 `boxId` 时不能用数组位置当作永久平台箱号；必须建立内部箱 ID 并标记待确认。
- API 地址不能绕过地址库和人工复核直接填入所有模板字段。
- 缺少主体、商品申报档案、税务/币种规则或正式模板时，只能生成草稿，不能生成已确认正式文件。

## 验收前置条件

- 已有真实账号的STA查询样本；继续补非STA、其他适用国家和异常类别，不将已有查询权限外推至其他接口。
- 覆盖单商品、多商品、多箱、混装、缺箱号和数量不一致场景。
- PO Number等于Reference ID、箱重尺寸以领星值为准和FBA实际箱数范围编号已由用户确认；仍需验证Reference双来源一致性及逐票输出。
- 继续验证箱号稳定性与箱序，落实独立实物复核、单位换算及已确认的两位小数格式；舍入方式及缺值处置规则仍待确定。
- 提供正式模板、模板版本、输出格式和一份人工已确认文件。
- 提供完整商品申报档案、主体档案、地址/渠道/税务/币种/价格规则。
- 至少用一个真实批次完成“同步 → 校验 → 人工确认 → 文件导出”并与人工结果逐字段核对。
