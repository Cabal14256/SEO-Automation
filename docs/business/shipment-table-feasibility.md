# 发货表格模块可行性与问题分析

公开脱敏摘要，更新：2026-10-19。保留设计结论和验证要求，原始业务工作簿、截图、数量分布、单元格定位及真实接口样本不公开。此页不代表重新完成业务验证；当前代码范围见[实现状态](../implementation-status.md)。

领星查询接口可提供货件商品与装箱字段，适合在明确店铺身份、完整分页、数量校验和人工确认后生成发货表。接口字段存在不等于实际账号有权限，也不保证每票历史货件完整。真实账号、非 STA 兼容、增量来源和现场实物签收需要独立验收。

| 目标 | 数据与实现方式 | 条件 |
| --- | --- | --- |
| 需求导入 | 人工上传、预览与确认，保留源行和首次业务日期 | 不能据历史表推定后续增量或缺失语义 |
| 货件商品 | `sid + FBA` 查询详情，保留 MSKU、FNSKU、SKU、品名和申报量 | 唯一关联货件，不从商品前缀猜店铺 |
| 每箱明细 | 装箱接口保存实际箱和箱内商品 | 平台箱标识可能缺失，使用稳定内部箱 ID |
| 人工分组 | 保存确认的货件成员集合 | 相同商品、配方或日期不授权跨组自动合并 |
| 数量与编码 | 逐商品守恒，按实际箱数编码 | 重复记录、冲突和缺字段阻止受影响组正式导出 |
| 库存备注 | 按成品仓与 SKU 查询库存快照 | 库存快照不代表已锁定或仍可用 |
| 发货表与 XLSX | 按确认版本生成商品、逐箱和月汇总 | 超过十箱不能截断，打印或导出后冻结 |
| 标签与物流单据 | 按各自规格及规则后续接入 | 制表不等于已取得标签接口权限或完成完整物流文件 |

## 核心接口

| 来源 | 请求 | 字段 |
| --- | --- | --- |
| 货件详情 | `POST /amzStaServer/openapi/inbound-shipment/shipmentDetailList` | `itemList` 的 msku、fnsku、productName、sku、quantity |
| 装箱 | `POST /amzStaServer/openapi/inbound-shipment/listShipmentBoxes` | 箱标识、箱名、重量尺寸、单位、`productList` 及 quantityInBox |
| 货件列表 | `POST /erp/sc/data/fba_report/shipmentList` | is_sta、计划 ID、当前/初始申报量、本地已发量、接收量 |
| 店铺 | `GET /erp/sc/data/seller/lists` | sid、名称、国家、站点与授权状态 |
| 本地库存 | `POST /erp/sc/routing/data/local_inventory/inventoryDetails` | SKU、仓库与 product_valid_num |

请求示例为虚构值，调用前通过私有配置替换：

```json
{
  "sid": 900101,
  "shipmentConfirmationId": "FBAEXAMPLE001"
}
```

公共鉴权参数和密钥只在服务端保存。按 appId 与接口管理限流、串行请求、完整分页和重试预算，分别记录连接错误、HTTP 状态、业务 code 与成功范围内无匹配；HTTP 200 不自动等于成功。

## 数据与模板风险

同一个“数量”字段可能指来源参考量、详情申报量、本地已发货量、接收量或逐箱合计，应独立保存。制表以详情申报量逐商品守恒，不能把出货前合法的已发货零值当成准备量，收货差异也不能反向修改原装箱。

历史格式可能出现“重量”列实际用于商品汇总或状态、所谓“仓库地址”存放目的 FC、日期和人员字段标题漂移等情况。适配器应展示实际表头、类型、公式和缓存，不能凭列名猜字段；缺值不补零，公式无可用缓存需要重新导出或人工确认。

月表和批次页可能重复展示同一业务，不能相加视为更多独立货件。不同 FBA 的相同商品和箱配方是合法同构数据；同一货件的完整记录重复须保留定位并人工处理。诊断性去重不能直接改写原件或确认数量。

实际箱与商品行分别存储，一箱多商品不重复计箱，商品跨箱不合并箱身份。相同总件数不能证明配方相同，配方多重集保留重复配方箱数。先保留人工确认组，再在组内重建配方、校验与编码；不把某个样例的固定货件数或箱数当通用规则。

重量尺寸保存原值与单位，换算 KG/CM 使用明确舍入规则和两位小数。API 登记值与现场实测分开记录；缺项、冲突、箱身份不明及确认失效应阻止最终导出。物流商、业务渠道、主体、申报、税务、价格与正式模板均需独立配置，不能由承运方式字段推断。

## 验收要求

完整流程需要“需求导入 → 人工分组 → 只读同步 → 差异处理 → 数量及箱序确认 → 编码 → 表格导出”，并与独立人工预期逐行核对。覆盖多商品、多箱、混装、商品跨箱、同配方不同组、重复记录、缺字段、空装箱和失败恢复。

真实验证还需覆盖国家、渠道、非 STA、跨次箱标识、装箱变更、分页、限流和续约。公开夹具只验证程序，不替代真实账号权限、现场实物或人工业务签收。具体规则见[箱分配算法](./us-allocation-algorithm.md)、[字段映射](./field-mapping.md)和[验收场景](../acceptance/scenarios.md)。
