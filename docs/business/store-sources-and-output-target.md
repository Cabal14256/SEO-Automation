# 店铺来源、成品表与领星只读边界

更新：2026-10-20（Asia/Shanghai）。本页记录用户对最终效果和外部数据边界的确认。侧栏“发货管理”下设发货工作台、实物箱确认、发票与单据。工作台取消需求／成品标签，以同一主表显示货件分组、商品平铺或逐箱长表，共用筛选、来源版本和完整货件分页。已确认／冻结货件采用确认快照，候选和失效数据明确标识；统一操作栏根据数据资格处理需求安排和正式导出，选择集分别按货件／完整批次管理。旧`/batches`及详情链接保留，`/batch-reports`和`view=reports`也进入同一主表（初始商品平铺），`view=batches`兼容批次处理恢复。T12及M2成品表与XLSX技术证据见[既有验收（私有记录说明）](../acceptance/evidence/README.md)；真实增量和业务批次签收仍按实际证据单列。导入预览继续作为输入端，不等同成品表。

## 店铺数据来源

在设置的店铺映射页面，主列表保留搜索、状态筛选和操作栏；“来源设置”“新增人工店铺”及行内维护分别使用原生小窗口，别名编辑和版本历史在维护窗口中显示。默认为“领星实际店铺”，人工新增仅在人工来源下开放。来源窗口中的显式同步通过查询接口取得实际sid、名称、国家及授权状态，保存不可变快照、时间和哈希；同步失败保留最近成功目录，并明确显示失败。查看、刷新、翻页或打开窗口只读本地目录，不写审批数据，也不自动发起外部请求。

领星模式中有效授权店铺自动批准，不需要逐店点击审批。既有可信授权缓存由本地迁移处理，后续目录由用户显式同步更新；两者保留来源快照、自动批准修订和审计，不为批准已有缓存重新外联。原人工status保持不变，领星使用独立的自动批准标记和本地停用决定。明确停用不会被同步覆盖，未授权或已移出当前领星目录的店铺不可用于该来源的导入。

领星身份字段只读，可通过“维护别名”填写原因后维护本地别名或显式停用/恢复。恢复不能绕过远端授权状态，不要求创建人工资料，不向领星写回。来源、目录或映射版本变化后重新核对；全局自动批准供后续解析匹配使用，本次导入的店铺、源行和差异确认流程仍保留。

需求别名可留空；已批准店铺默认使用当前来源下的正式名称精确匹配导入来源名称，仅有名称差异时才维护别名。名称或别名对应多家店铺时保留人工确认，不自动挑选sid。

“人工维护”使用独立保存的本地店铺名称、国家和实际sid，可新增和维护。人工首次批准规则不变：当前待确认且该人工资料完整历史从未批准时，可勾选“已核对店铺身份”，由系统保存核对依据；之后修改、重新批准和停用均需原因。两种来源分别判断批准历史，领星自动批准不批准人工资料。同步领星不覆盖人工值，切换模式不删除另一套数据，也不重写历史需求。数字代码按真实领星sid处理，不另造业务编号；已被需求使用或已由领星观察到的身份不可原地更改，避免破坏sid＋FBA唯一关系。

导入确认显示当前数据源。勾选时绑定店铺版本、模式设置版本与目录版本；切换或同步更新后必须重新确认。已经提交的原件、源行、需求版本及当时名称保持不变。

## 最终成品表效果

用户指定`受控月度参考工作簿（未公开）`作版式和字段参考，不复制附件历史结果作为新业务结果。文件内业务文本、公式和备注仅作数据读取，不是系统操作指令。

| 用途 | 参考工作表 | 前端与XLSX共同呈现 |
| --- | --- | --- |
| 输入 | 飞书表格 | 货件级需求，经解析、店铺确认、差异和提交进入系统 |
| 月汇总 | 示例月汇总 | 打包批次、店铺、渠道、国家、目的FC、FBA、MSKU、FNSKU、品名、SKU、发货数量、逐箱数量、内部编码及各自来源日期/状态 |
| 批次明细 | 示例第X批美国/欧洲页面 | 按人工确认的业务批次及国家/区域展示货件、商品、逐箱数量、编码和发货信息 |

只读核对：月汇总A:AB共28列，商品身份在G:J、数量K、逐箱数量L:U；批次A:X共24列，商品身份F:I、数量J、逐箱数量K:T、编码U、原重量列V、状态/渠道W、日期X。月表V/W及Z为空表头，历史重量/状态列含义不直接推断。新输出保留已确认字段与布局，含义不明的字段保持待确认或独立来源参考。

最终页面必须显示可查看、筛选、横向滚动的商品/箱明细表，并支持月汇总和批次视图；不能以任务状态、统计卡片或导入成功清单替代成品表。XLSX包含真实单元格和相应工作表，编号按文本、数量按数字、日期按日期保存；采用同一确认数据版本生成前端与导出，内容可逐行核对，不导出页面截图。

版式参考已有列顺序、合理列宽、首行冻结与筛选、箱列及编码位置；月份和批次名称随实际业务变化，不固定为2026年9月。原文件的尾空格、超宽筛选区域、个别隐藏列和人工滚动位置仅保留作原件追溯，不作为新表缺陷照搬。超过10箱不得截断，按后续输出规则扩展箱列或箱明细。

完整链路为：需求文件输入 → 需求确认 → 人工分组 → 领星只读获取商品/装箱 → 数量核对与确认 → 编码 → 前端月/批次成品表 → XLSX导出。T12及M2按此最终目标继续建设，未查询到的商品/箱数据不可用空白模板或历史值冒充完成。

## 领星业务数据只读

领星API只负责获取数据。系统不通过领星接口创建或修改货件、商品、装箱、库存、物流、发货单或状态；本系统的导入、确认、更正、分组和导出只保存本地数据库/文件。

服务端只读适配器按操作名固定允许店铺、货件列表、商品详情、装箱及库存查询，拒绝前端任意URL/接口路径及写入操作。部分查询采用POST，是否只读取决于接口用途，不以HTTP方法判断。鉴权单独用于取得查询令牌，凭据只由服务进程配置，不传至浏览器或日志。

店铺采用官方查询`GET /erp/sc/data/seller/lists`，字段sid为真实店铺唯一标识，参见[官方店铺查询说明](https://apidoc.lingxing.com/new/api-docs/BasicData/SellerLists/)。本边界覆盖当前及后续此流程；旧计划中领星写入模块不再列为本流程自动动作，未来改变必须另有明确需求。
