## 文件生成所需的非领星字段

以下字段不能由已审货件接口直接补齐，必须从项目主数据、模板配置或人工确认取得：

- 运输方式缺失时的人工确认值、物流商及其国家映射；在线运输方式候选可读取关联发货单的 `method_name`，不由 Amazon 配送类型推导。
- 报关方式、交税方式、VAT/递延规则、默认币种和国家例外。
- 最终中英文申报品名、材质、用途、品牌、型号、HS、数量单位。
- 申报单价、最低申报价比例、汇率、精度、四舍五入和尾差。
- 卖方/经营/生产销售主体、税号、地址、联系方式、发票编号和日期。
- 示例物流商货箱编号按上述已确认公式在本地生成；开船日期、预计送仓时效和文件命名规则仍需独立配置。
- 正式模板版本、输出格式和人工确认样例。

领星平台商品的 `productName`、`title`、`url`、`asin_url` 和图片只能作为商品档案的候选来源；不能自动替代报关申报字段。

## 商品唯一键

逻辑商品身份：

```text
sid + FBA货件号 + MSKU + FNSKU + SKU
```

装箱分配指纹在商品身份上追加规范化的箱内数量分布。重复检测使用完整业务键；不同 FBA 的相同商品行属于正常同构数据，不应误删。

用于跨货件识别同配方时，在同 sid 和确认业务组范围内使用 `(MSKU,FNSKU,SKU,数量)` 排序数组，不包含 FBA；这是配方比较键，不取代上面的货件商品身份。普通集合会丢失相同配方的实际箱频次，应使用配方多重集。

## 数量校验

```text
商品总量 = Σ(该商品在所有箱中的箱内数量)
```

装箱合计与业务确认对照量不一致时保留原值、系统计算值、差额和来源快照，阻止该子批次正式导出。详情与列表数量冲突单列待确认；少收/多收另列接收差异，不反向修改原装箱。当前脚本仅按 MSKU + FNSKU 聚合做探测，正式算法必须包含 SKU 和 sid/FBA 作用域，不能把脚本核对误认为完整生产身份规则已经实现。

参考导入需同时保留原表合计和疑似重复标记；诊断性的去完全重复行后结果单列，不能静默取代原表。缺值/缺行/分页未完成不能补 0；明示已发货量、接收量为 0 可保留。运算按每箱、每票商品、整组商品、编码箱数分层核对。

## 导出字段

发货记录至少包含：周批次、子批次、店铺、渠道、国家、目的 FC、FBA 货件号、MSKU、FNSKU、品名、SKU、商品总量、逐箱数量、编码、状态、数据版本和导出时间。历史模板中的“重量”列不得直接映射为真实重量，重量必须独立保存。
