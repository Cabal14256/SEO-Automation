# US 箱分配与编码算法

公开脱敏版本，更新：2026-10-19（`Asia/Shanghai`）。本页保留算法与业务约束，不发布真实店铺、货件、商品、数量分布或工作簿定位。下方数值示例为独立编造，用于解释规则，不是历史业务证据。当前授权以[业务规则](./rules.md)为准。

## 输入、身份与分组

输入至少包含 `sid + FBA`、来源行和人工确认的业务子批次。FBA 去首尾空格并转大写，其他商品标识保留原值。店铺名称和别名必须来自明确映射；例如虚构来源名 `EXAMPLE-US` 对应正式名 `EXAMPLE-US-US`，不能据名称相似度、商品或货件前缀猜测归属。

无上游业务组标识时，可按 `sid + sta_inbound_plan_id` 提出候选，成员集合仍须人工确认。同 sid、国家、渠道范围内允许人工跨计划合组或同计划拆组；相同商品、配方、日期、目的仓或送达窗口不授权自动合并。不固定每组货件数、每票箱数或每箱件数。

周批次采用上海时间周一至周日。业务日期固定为成功接收本次导入时的上海日期，重试、解析和确认跨日不改变。API 创建、计划、发货和送达日期分别保留。同货件再出现不自动移动或复制既有需求，更正走版本确认。

| 对象 | 作用域与键 | 约束 |
| --- | --- | --- |
| 货件 | `sid + 标准化FBA` | 响应必须唯一匹配当前货件 |
| 货件商品 | `sid + FBA + MSKU + FNSKU + SKU` | 相同 SKU 的不同标签商品不能合并 |
| 配方商品 | 同 sid 下的 `(MSKU, FNSKU, SKU)` | 比较跨货件配方时保留店铺边界 |
| 实际箱 | 内部箱 ID，关联货件与外部箱标识 | 一个箱只属于一个货件；箱名和显示码不作全局键 |

详情按 `sid + shipmentConfirmationId` 关联；装箱优先按列表 `sta_shipment_id` 与返回 `shipmentId` 唯一关联。多组归属不明、缺字段、空装箱或分页不完整时保留异常，不展平拼成当前货件。

分别保存 `boxId`、`packageId`、`localBoxId`、`boxName/box_name` 与内部箱 ID。兼容两种箱名字段，冲突时待核对。平台箱名可能不连续，货件内序号可跨 FBA 重复，接口数组下标不能成为永久身份。首次箱序可参考 `localBoxId`，人工确认后保存顺序版本，刷新不能静默重排。

## 配方、数量与重复检测

检查完整身份、有效数量、重复记录和箱归属后，将每箱 `(MSKU, FNSKU, SKU, quantityInBox)` 按身份固定文本顺序排序，用结构化数组序列化计算配方指纹。忽略输入商品顺序，保留所有实际箱及其箱内商品。

- 只有完整商品身份和对应数量均相等才是相同配方；总件数、SKU、颜色、重量或尺寸相同均不充分。
- 同箱相同完整身份重复出现先标异常，不直接合并以掩盖重复。
- 整票或整组比较配方多重集，保留每种配方实际箱数；普通去重集合会丢掉重复配方的箱。
- 同组可包含多种配方，不重新均分商品，不从总量计算“最优装箱”。包装、有效期和预处理等兼容条件需要独立确认。

```text
Q_box[s,i] = Σ货件 s 的每个实际箱内商品 i 的数量
N_group = Σ成员货件的实际箱数
T_group[i] = Σ成员货件 Q_box[s,i]

只有全部箱共享同一配方 p 时：
Q_box[s,i] = n_s × p[i]
T_group[i] = N_group × p[i]
```

以详情申报量逐商品校验装箱守恒，分别保存列表当前申报量、初始申报量、本地已发货量和接收量。明确零值合法，缺字段或无完整分页为未知，不能补零继续。箱内数量须为有效正整数。

| 差异 | 处理 |
| --- | --- |
| 装箱合计与对照量不一致 | 保留原值及差额，阻止受影响子批次正式导出 |
| 详情与列表申报量冲突 | 单列接口冲突，不静默覆盖 |
| 收货少收或多收 | 独立展示，不反向修改已确认装箱 |
| 同一货件完整记录重复 | 保留来源定位并人工处理；去重仅作诊断 |
| 不同 FBA 有相同商品或同配方 | 保留各自货件和箱，不误删合法同构数据 |

虚构示例：某货件申报 24 件，原始来源合计 30 件，其中一条完整记录重复 6 件。诊断去掉重复后吻合，只能提示原因；正式处理仍需人工确认并保留新版本。另一虚构示例中，两组的配方相同，第一组 3 箱、第二组 2 箱，成员集合不同，不能全局合并成一个 5 箱组。

## 编码、变更与导出

子批次是确认、编码和导出的业务边界。按当周人工确认组序分配 `A…Z、AA…`，按组内实际箱数编码；默认组序取最小标准化 FBA，允许人工调整。货件按标准化 FBA 纯文本排序，货件内箱序以确认版本为准。

保存“外部货件/箱标识 ↔ 内部箱 ID ↔ 显示编码 ↔ 确认版本”。追加成员保留原前缀和旧箱码，新箱用后续序号；移除仅作废被移除箱码；合并、拆分、移动使影响组旧码失效。已导出或已打印后冻结，更正建立新组、新前缀和版本，旧文件继续可追溯。

箱数按内部箱 ID 去重，不按商品行或配方种类计数。超过十箱时动态扩列并附逐箱明细，不截断。月归属采用首次业务日期。商品数量汇总不作为重量，原始重量尺寸和单位、换算结果、线下实测与确认分别保存。

```text
读取来源 → 校验身份 → 逐票快照 → 唯一关联货件和箱
→ 检测缺字段、数量和重复 → 人工确认分组与箱序
→ 逐商品及整组守恒 → 编码预览 → 版本确认 → 导出
```

HTTP 200 仍检查业务 code；授权失败、超时、分页不完整和成功范围内查无结果分开记录。单票失败保留成功快照，异常组阻止导出，同周其他正常已确认组可继续。恢复只处理失败或未完成范围，请求预算不能自动无限扩大。

原始研究与真实验收资料仅在受控本地保存，见[私有研究说明](../research/README.md)和[证据说明](../acceptance/evidence/README.md)。实际账号授权、非 STA 兼容、跨次箱身份、装箱变化、分页、限流和 token 续约仍应按具体环境验证；公开数值示例不替代业务签收。
